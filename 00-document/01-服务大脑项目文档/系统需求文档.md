## 三、系统边界与职责划分

### 3.1 定位

本项目交付的是**被 GSI 调用的 Agent 服务**。工程形态为前后端一体仓库：后端为交付主体，前端仅保留基座既有管理页面（日志审计、监控等），不新增业务页面。

### 3.2 职责划分（强制口径）

| 能力 | GSI | Agent 服务 | 说明 |
| --- | --- | --- | --- |
| 工单/录音/ASR/CTI 数据 | 生产与持有 | 只消费 | Agent 不创建、不修改业务事实 |
| 权限计算（部门/项目/指定人） | 计算 | 只接受白名单快照 | 禁止 Agent 自行推断权限 |
| 知识业务状态（草稿/审批/发布） | 维护 | 只接收"正式切片" | 停用/删除以事件下发 |
| 知识切块与向量 | 不参与 | 生成与维护 | 切块 ID 与 GSI 条目 ID 建立映射 |
| 质检规则内容的业务口径 | 业务确认 | 只做配置校验与执行 | 规则文本由业务 Owner 维护 |
| 判定结论 | 展示与复核 | 产出判定与证据 | 最终绩效结论以复核为准 |
| 会话与历史消息 | 展示 | 托管与查询 | 归属校验按 `tenant_id + user_id` |
| 反馈（点赞点踩） | 采集 | 不参与 | Agent 保证 `session_id`/`message_id` 稳定 |

### 3.3 系统上下文

```
        ┌──────────────┐        ①/v1 契约调用（HMAC 签名）
        │   GSI 业务系统 │ ────────────────────────────────┐
        │  工单/录音/知识 │                                 ▼
        │  权限/报表/前台 │ ◄──── ②判定与问答结果（JSON） ┌───────────────────┐
        └──────────────┘                                │  Agent 服务        │
                                                        │  ┌──────────────┐ │
        ┌──────────────┐   ③嵌入/重排（内网 HTTP）        │  │ LangGraph 编排│ │
        │ 私有化模型服务 │ ◄────────────────────────────── │  └──────────────┘ │
        │ bge-m3 / rerank│                                 │  ┌──────────────┐ │
        └──────────────┘                                 │  │ PostgreSQL   │ │
                                                         │  │ + pgvector   │ │
        ┌──────────────┐   ④对话补全（HTTPS）             │  └──────────────┘ │
        │ AWS Bedrock   │ ◄────────────────────────────── │                   │
        │ OpenAI 系列模型│                                 └───────────────────┘
        └──────────────┘
```

## 四、角色与用例

| 用例 | 角色 | 触发 | 主流程 | 结果 |
| --- | --- | --- | --- | --- |
| UC-01 知识入库 | 知识 Owner（经 GSI） | 文档/FAQ 变更 | 提交解析 → 轮询进度 → 校对 → 提交正式切片 | 知识可检索，旧版本被替换 |
| UC-02 知识下架 | 知识 Owner（经 GSI） | 知识过期 | 下发 DISABLE / DELETE 事件 | 该发布单元不可召回 |
| UC-03 坐席问答 | 坐席（经 GSI） | 客户提问 | 创建会话 → 提问 → 得到带引用答案 | 答案 + 引用条目 + 会话留痕 |
| UC-04 无依据拒答 | 坐席（经 GSI） | 问题超出知识范围 | 召回无命中或低于阈值 | 明确返回"无依据"，不生成推测 |
| UC-05 单通质检 | 质检流程（经 GSI） | 通话结束 | 转写 → 四类判定 → 计分 → 产出单通结果 | 分数 + 缺陷 + 证据片段 |
| UC-06 一致性校验 | 质检流程（经 GSI） | 坐席回答涉知识 | 召回相关条目 → 比对 → 标注差异 | 一致/不一致 + 差异说明 |
| UC-07 报告生成 | 项目经理 | 周期结束 | 聚合统计 → 生成解读文字 | 员工/团队报告 |
| UC-08 复盘申诉 | 质检员/坐席 | 对结论有异议 | 提交复核 → 修正判定 → 回流样本 | 判定可修正，样本可回灌 |
| UC-09 效果监控 | 模型运营 | 每周 | 查看判定分布、拒答率、引用命中率 | 调优依据 |
| UC-10 联调自检 | GSI 开发 | 上线前 | 13 接口逐个打通正常/异常用例 | 联调记录 |

## 五、功能需求

### 5.1 集成与接入（FR-INT）

| 编号 | 需求 | 优先级 | 验收标准 |
| --- | --- | --- | --- |
| FR-INT-01 | 必须提供 13 个 `/v1/*` 接口，路径、方法、字段与 `gsi-ai-openapi.json` 完全一致 | P0 | 契约比对脚本 0 差异 |
| FR-INT-02 | 全部对外接口必须使用 HMAC-SHA256 五头签名鉴权，不挂 JWT Bearer | P0 | 缺头/错签/过期/重放四类用例均被拒，错误码符合契约 |
| FR-INT-03 | 签名原文必须使用原始请求路径（含查询串）与原始请求体字节摘要，禁止中间件重排 JSON 或改写路径 | P0 | 含中文、含转义、含空 body 三类用例签名通过 |
| FR-INT-04 | 必须实现 nonce 持久化防重放，窗口 ±5 分钟，多实例共享 | P0 | 同 nonce 二次请求被拒；服务重启后仍拒绝 |
| FR-INT-05 | 必须实现三类幂等台账（`job_id` / `event_id` / `request_id`），同 ID 不同正文返回 409 | P0 | 重试同正文返回首次结果；异正文 409 |
| FR-INT-06 | 错误响应必须为 `{error:{code,message,retryable}}`，覆盖契约定义的业务码 | P0 | 14 类错误码逐一可复现 |
| FR-INT-07 | `DELETE` 接口必须接收 JSON 正文；反向代理不得丢弃 | P0 | 经网关后仍能读取正文（上线检查单验证） |
| FR-INT-08 | 查询类接口必须支持游标分页，游标不可被篡改利用 | P1 | 越权游标返回空/错误，不泄露他人数据 |

### 5.2 知识接入（FR-KB）

| 编号 | 需求 | 优先级 | 验收标准 |
| --- | --- | --- | --- |
| FR-KB-01 | 必须支持文档与 FAQ 两类来源提交解析任务，返回 `202` 与 `job_id` | P0 | 同一 `job_id` 重复提交不重复执行 |
| FR-KB-02 | 解析任务必须具备四态：`queued` / `running` / `succeeded` / `failed`，并暴露 `progress` | P0 | 各态可构造并查询到 |
| FR-KB-03 | 解析失败必须以 HTTP 200 返回任务失败（`error_code`/`error_message`），与请求失败区分 | P0 | 非法文件返回任务失败而非 4xx/5xx |
| FR-KB-04 | 解析产物 `chunks` 必须包含 `seq`、`heading`、`content`、`page_from`、`page_to`、`source_type`，且不得含向量 | P0 | 结构与契约一致；响应体中无向量字段 |
| FR-KB-05 | 必须输出 `pages`（页图引用、宽高、有效期）与 `suggested`（建议业务单元/主题）与 `warnings` | P1 | 无页图能力时返回空数组且不报错 |
| FR-KB-06 | 索引必须支持 REPLACE / DISABLE / DELETE 三种操作，同步返回 `200` | P0 | 三操作语义用例通过 |
| FR-KB-07 | 发布单元必须维护单调递增 `revision`；旧版本事件返回 409 与 `STALE_REVISION` | P0 | 乱序事件被拒且不污染现网版本 |
| FR-KB-08 | 新版本必须原子切换：切换瞬间检索不到半成品，切换后旧版本保留可回退 | P0 | 并发检索+切换用例无中间态命中 |
| FR-KB-09 | 相同 `content_hash` 不得重复向量化；回执必须给出 `searchable` 与 `accepted_chunk_count` | P1 | 重复内容二次提交计数正确、耗时可测下降 |

### 5.3 检索与问答（FR-RAG）

| 编号 | 需求 | 优先级 | 验收标准 |
| --- | --- | --- | --- |
| FR-RAG-01 | 必须支持两种模式：关键词检索与自然语言检索 | P0 | 两模式均可返回 `snippet` 与 `score` |
| FR-RAG-02 | 自然语言模式必须向量召回 + RRF 融合 + rerank 精排 | P0 | 关闭 rerank 与开启的结果排序有差异且可复现 |
| FR-RAG-03 | 检索必须在 `allowed_snapshots` 白名单内进行，禁止先全库召回再隐藏 | P0 | 越出白名单的切块 0 命中（用例证明，含 SQL 执行计划佐证） |
| FR-RAG-04 | 空白名单必须返回空命中，不得退化为全库检索 | P0 | 空白名单返回空结果且无异常 |
| FR-RAG-05 | 白名单规模超上限必须返回 413 与 `SCOPE_TOO_LARGE` | P1 | 超大名单被拒且错误码正确 |
| FR-RAG-06 | 召回为空或最高分低于阈值时必须返回"无依据"，禁止生成推测答案 | P0 | 库外问题 20 例抽查 0 编造 |
| FR-RAG-07 | 生成必须为非流式；`stream=true` 返回 `UNSUPPORTED_STREAM` | P0 | 参数校验用例通过 |
| FR-RAG-08 | 答案必须附带引用（条目 ID、切块 ID、标题、片段），引用编号与正文标记一一对应 | P0 | 引用可定位到切块；伪造编号被拒 |
| FR-RAG-09 | 生成超时（默认 60 秒）不得丢请求，必须可经结果查询接口取回 | P0 | 超时后查询返回执行中/最终结果 |
| FR-RAG-10 | 会话必须支持多轮上下文，上下文窗口按 token 预算截断且保留系统指令与最近轮次 | P1 | 长会话不超模型上下文；关键指令不丢 |
| FR-RAG-11 | 历史消息中若其知识依赖已失效，该条回答与引用必须整条隐藏 | P1 | 停用知识后查询历史不返回该回答 |

### 5.4 质检判定（FR-QC）

| 编号 | 需求 | 优先级 | 验收标准 |
| --- | --- | --- | --- |
| FR-QC-01 | 必须实现四类判定：硬规则、语义规则、知识一致性、工单一致性 | P0 | 四类各 ≥3 条真实规则跑通 |
| FR-QC-02 | 硬规则必须由规则引擎执行，支持关键词、正则、枚举、字段校验、时长/静音阈值五类判定方式 | P0 | 每种判定方式有单测；不调用模型 |
| FR-QC-03 | 语义规则必须输出结论 + 证据片段（说话人、时间区间、原文）；无证据视为未判定 | P0 | 抽检 20 例均有证据或明确未判定原因 |
| FR-QC-04 | 知识一致性判定必须先召回再比对；召回为空时结论为"无法判定"而非"不一致" | P0 | 无相关知识用例返回无法判定 |
| FR-QC-05 | 工单一致性判定必须逐字段比对（Caller / Category / Subcategory / Type / Priority / 状态原因） | P0 | 字段级差异清单可输出 |
| FR-QC-06 | 规则必须可配置：名称、分类、适用范围、触发条件、判定方式、分值、知识依据、示例、优先级、生效时间、版本 | P0 | 业务侧改配置不改代码即可生效 |
| FR-QC-07 | 判定结果必须结构化：规则 ID、结论、分值、维度、缺陷标签、风险标签、证据 | P0 | 结构字段齐全可入库 |
| FR-QC-08 | 缺陷标签必须映射到一级缺陷分类树（服务规范/业务知识/沟通技巧/解决能力/合规风险/工单处理/情绪处理） | P0 | 未映射标签被拒绝入库 |
| FR-QC-09 | 计分必须支持维度分 + 总分；维度至少含服务规范、业务准确性、问题解决、沟通体验、合规风险、工单规范性 | P0 | 权重可配置，单测覆盖加减分边界 |
| FR-QC-10 | 判定结论必须带复核状态（待复核/通过/修正），修正需留原值 | P0 | 修正后历史可查、原值不丢 |
| FR-QC-11 | 四类判定必须可并行执行，单类失败降级为"该类未判定"，不得整体失败 | P0 | 注入单类故障，其余三类仍产出 |
| FR-QC-12 | 判定必须可重复：同输入同配置同模型版本下结论稳定（温度与采样参数受控） | P1 | 同输入连续 5 次结论一致率 ≥ 90%（语义类允许阈值内波动） |

### 5.5 报告与分析（FR-RPT）

| 编号 | 需求 | 优先级 | 验收标准 |
| --- | --- | --- | --- |
| FR-RPT-01 | 必须支持四层报告：单通、员工、团队/项目、Findings | P0 | 四层均可按周期生成 |
| FR-RPT-02 | 报告中所有数字必须由 SQL 聚合产出，模型只生成文字解读，禁止模型输出数字 | P0 | 报告数字与库内聚合结果逐项一致 |
| FR-RPT-03 | 单通报告必须含：总分、维度分、命中规则、关键缺陷、亮点、知识/工单一致性对比、风险标签、证据片段、改进建议 | P0 | 字段与上游方案 §5.1 对齐 |
| FR-RPT-04 | 员工报告必须含：周期趋势、维度变化、高频缺陷/亮点、与团队均值对比、典型案例、成长阶段（L1–L5） | P1 | 成长阶段有判定规则且可解释 |
| FR-RPT-05 | 团队/项目报告必须含：整体得分、覆盖率、缺陷/风险分布、主题排名、团队对比、知识库不匹配 Top | P1 | 覆盖率口径与 GSI 一致 |
| FR-RPT-06 | Findings 必须含标题、描述、影响范围、根因、证据样本、风险等级、建议动作、责任人、跟踪状态 | P1 | 可导出且可跟踪状态流转 |
| FR-RPT-07 | 报告生成必须异步可查（长任务不阻塞请求），失败可重试且不产生重复数据 | P0 | 重试幂等验证 |

### 5.6 Agent 编排（FR-AGT）

| 编号 | 需求 | 优先级 | 验收标准 |
| --- | --- | --- | --- |
| FR-AGT-01 | 必须使用 LangGraph 显式状态图编排，节点职责单一、可单独测试 | P0 | 每节点有单测；图结构可导出 |
| FR-AGT-02 | 图必须支持条件分支（如召回为空直接终止生成）与并行汇聚（四类判定） | P0 | 分支与汇聚路径均有用例 |
| FR-AGT-03 | 每个节点必须有超时预算，整体超时可被上层感知并转为可查询状态 | P0 | 注入慢节点，整体按预算降级 |
| FR-AGT-04 | 节点失败必须可重试（幂等节点）或可降级，禁止无限重试 | P0 | 重试次数与退避可配置，超限落失败态 |
| FR-AGT-05 | 编排状态必须落库（任务状态机 + 中间结果），重启后可恢复或明确失败 | P0 | 重启后任务不悬挂 |
| FR-AGT-06 | 必须记录 `request_id` 贯穿全链路，日志不落原文正文与密钥 | P0 | 按 `request_id` 可还原调用链 |
| FR-AGT-07 | 必须限制工具调用范围（仅知识检索、工单查询、规则查询、报告数据查询），禁止任意执行 | P0 | 未注册工具调用被拒 |

### 5.7 运营治理（FR-OPS）

| 编号 | 需求 | 优先级 | 验收标准 |
| --- | --- | --- | --- |
| FR-OPS-01 | 规则必须支持版本与生效时间，支持灰度和快速回滚 | P1 | 回滚后判定恢复旧口径 |
| FR-OPS-02 | 知识必须支持 Owner 机制与生效/失效时间，过期自动告警 | P1 | 过期条目不参与检索 |
| FR-OPS-03 | 必须支持复核与申诉闭环：复核结论回写判定、申诉记录可查 | P1 | 闭环状态可追踪 |
| FR-OPS-04 | 人工修正样本必须可回灌为评估集，用于规则与提示词调优 | P2 | 导出格式可直接用于评测 |
| FR-OPS-05 | 必须提供效果监控：判定分布、拒答率、引用命中率、平均耗时、失败率 | P1 | 指标可按日聚合查询 |
| FR-OPS-06 | 提示词模板必须版本化，变更需留痕（改动人、时间、对比结果） | P1 | 模板可回滚 |
| FR-OPS-07 | 敏感操作（规则变更、知识删除、密钥轮换）必须审计 | P0 | 审计记录含操作人、时间、前后值 |

## 六、模型与算法需求（MR）

| 编号 | 需求 | 优先级 | 验收标准 |
| --- | --- | --- | --- |
| MR-01 | 对话模型必须经 AWS Bedrock 调用 OpenAI 系列（ChatGPT 类）模型；`model_id`、区域、配额全部走配置 | P0 | 改配置即切换模型，无需改代码 |
| MR-02 | 必须支持主备模型降级：主模型不可用/超配额时切换备选并记录降级事件 | P1 | 断网或配额耗尽自动降级 |
| MR-03 | 向量化必须使用私有化部署的 embedding 模型（bge-m3，输出 1024 维） | P0 | 向量维度与库表、索引一致；语料不出内网 |
| MR-04 | 重排序必须使用私有化部署的 rerank 模型（bge-reranker-v2-m3），支持 `top_n` | P0 | 精排结果与关闭精排结果可对比 |
| MR-05 | 嵌入/重排服务不可用时，检索必须降级为关键词通道并显式标记 `degraded` | P0 | 停掉模型容器，检索仍可用且标记降级 |
| MR-06 | 所有模型调用必须设置超时、重试上限与并发上限，禁止请求堆积 | P0 | 压测下无雪崩；超限返回可重试错误 |
| MR-07 | 模型输出必须结构化受控（JSON Schema 或函数调用），解析失败按未判定处理 | P0 | 注入非法输出不污染判定表 |
| MR-08 | 生成参数（温度、最大 token）必须按场景配置：判定类低温、问答类可略高 | P0 | 配置项存在且生效可验证 |
| MR-09 | 必须记录每次模型调用的模型标识、耗时、token 用量，用于成本核算 | P1 | 可按日汇总 token 与费用估算 |

## 七、数据需求（DR）

| 编号 | 需求 | 优先级 | 验收标准 |
| --- | --- | --- | --- |
| DR-01 | Agent 数据必须落在独立 schema（`ai_knowledge`），与业务表同库不同 schema | P0 | GSI 账号无法访问该 schema |
| DR-02 | Agent 账号必须按 schema 最小授权（仅本 schema 的 DML/DDL 所需权限） | P0 | 越权访问被数据库拒绝 |
| DR-03 | 必须建齐七类实体：解析任务、发布单元、切片、幂等台账、会话、消息、请求台账 | P0 | 迁移脚本可空库重建 |
| DR-04 | 向量表必须建 HNSW 余弦索引，维度与 embedding 输出一致 | P0 | 执行计划命中索引；维度不符启动即失败 |
| DR-05 | 不得保存通话录音原文件；转写文本按最小必要保存并可配置留存期 | P0 | 库内无音频二进制；留存策略生效 |
| DR-06 | 日志与台账中不得出现完整原文、密钥、令牌 | P0 | 抽检日志无敏感字段 |
| DR-07 | 送模型的文本必须做字段级最小化与 PII 脱敏（账号、手机号、邮箱按规则掩码） | P0 | 脱敏用例通过；提示词中无可识别个人标识 |
| DR-08 | 数据迁移必须只走 Alembic，禁止手工改表；变更需附回退说明 | P0 | 升级/回退双向可执行 |
| DR-09 | 删除类操作必须可审计且软删优先（除明确要求物理删除） | P1 | 删除后可追溯并支持恢复窗口 |

## 八、非功能需求（NFR）

### 8.1 性能

| 编号 | 指标 | 目标 |
| --- | --- | --- |
| NFR-P-01 | 检索接口（不含生成）P95 | ≤ 800 ms |
| NFR-P-02 | 非流式生成整体 | ≤ 60 s（超时转可查询） |
| NFR-P-03 | 索引单次请求（契约范围内切片规模） | ≤ 60 s，超出走分批 |
| NFR-P-04 | 解析任务吞吐 | ≥ 100 份/小时（单实例，视文件规模） |
| NFR-P-05 | 并发会话 | ≥ 50 并发，无 5xx |

### 8.2 可靠性

| 编号 | 要求 |
| --- | --- |
| NFR-R-01 | 服务可用性 ≥ 99.5%（单实例 + 快速重启） |
| NFR-R-02 | 任务表状态机不得出现悬挂态；重启后超时任务标记失败并可重试 |

## 十一、需求验收流程

1. **自测**：开发按本文 §五、§八逐条构造用例，产出执行记录；
2. **联调**：GSI 按 UC-10 逐接口验收，差异记入缺陷清单；
3. **业务抽检**：质检团队按规则抽样 20–30 通，验证判定与证据可读性；
4. **验收签字**：三项通过后由业务负责人确认；未通过项列入二期或走变更。
