## 二、逐项可行性结论

### 2.1 四头 HMAC 签名（T0.1）

| 结论 | 说明 |
| --- | --- |
| **可行** | 7 行签名原文（版本 / client_id / 时间戳 / nonce / 大写法 / 原始 path+query / 正文 SHA-256 小写 hex，LF 连接、末尾不留空行）在双方都能稳定重建 |
| 已验证 | 缺头、签名不符、时间戳越窗（±5 分钟外）、nonce 重放 四类均返回 401 `unauthorized`；GET 无正文按空字节序列计算摘要，与契约「对空字节序列计算签名摘要」一致 |
| 已验证 | `authorization.issued_at/expires_at` 跨度 > 120s 被拒（冒烟用例 #14，POC 用 400，错误码见 Q1）；已过期被拒（单测覆盖，错误码见 Q2） |
| 待正式化 | nonce 只存进程内存：多副本部署必然漏判重放，且重启后清零 → **T1.1 必须落 Redis/DB 并带 TTL**（TTL ≥ 2×时钟窗口，即 ≥10 分钟） |

### 2.2 解析链路 `#01 → #02`（T0.2）

| 结论 | 说明 |
| --- | --- |
| **可行** | `file_url` 真实 HTTP 拉取 → 解析 → 分片 → 落任务表；`#02` 轮询从 `queued` 到 `succeeded` 正常，`result.chunks` 带 `seq/heading/content/page_from/page_to`，未携带任何向量字段（符合契约） |
| 已验证 | `#01` 202 的 `status` 只取 `queued/running/succeeded`（契约枚举）；同 `job_id` 同正文重试返回首次回执；`#02` 查不存在的任务 404 `not_found`；`failed` 走 200 + `error_code/error_message` |
| 已验证 | 解析产物**只落任务表、不自动进检索库**（契约「解析产物为待确认草稿，ai 不得自动写入正式检索库」） |
| 未覆盖 | `pages` 恒为 `[]`（契约允许，但 GSI 编辑预览需要页图）→ **本侧能力缺口，必须在 T2.4 补齐**，否则前端预览不可用；`metadata.units` / `audience` 仅透传，未参与解析 |

### 2.3 写入与向量化 `#03`（T0.2）

| 结论 | 说明 |
| --- | --- |
| **可行** | GSI 侧给定的完整切片集合 → 校验（非空 / `chunk_id` 唯一 / `seq` 连续 1..n）→ bge-m3 向量化（1024 维）→ pgvector 落库（HNSW cosine）→ 回执 `accepted_chunk_count / searchable / revision` |
| 已验证 | 首次发布 201；同 `request_id` 同正文重试 201 且有回执（不重复写）；换 `request_id` 同 `publication_id` 409；失败请求整体回滚，不留半成品 |
| 已验证 | 3 条切片端到端 1.49s，其中向量化 1.45s（单批 ≤16 条的一次远程调用固定开销约 1.4s） |
| 未覆盖 | `content_hash` 只存不校验（规则待定，见 Q9）；`revision` 单调性未校验（POC 只有首发布场景，见 Q14）；无修订/删除四路径（T3.2/T3.3） |

### 2.4 检索 `#07`（T0.3）

| 结论 | 说明 |
| --- | --- |
| **可行** | `keyword` 单走关键词；`natural_language` 走「向量召回 20 + 关键词召回 20 → RRF(k=60) 融合 → 取前 N」；两种模式在 3 切片样例上都能召回 |
| 已验证 | `returned_count == len(hits)`、`no_evidence` 与 `hits` 空否一致；命中项按契约投影（**不回 `content`**，只给 `snippet`） |
| 已验证 | 端到端 0.49~0.74s，其中查询向量化约 0.70s → 检索延迟几乎全在 embedding 侧 |
| 未覆盖 | **无权限过滤**（契约要求「ai 从指定表计算实时授权」，POC 召回全库）→ **T4.3 是本期最高风险项**；无 rerank；`score` 口径见 Q5 |

### 2.5 生成与引用 `#14`（T0.3）

| 结论 | 说明 |
| --- | --- |
| **可行** | GSI 下发的 `prompt_text` 原样作为 system 提示词，AI 只追加「引用格式要求」一节；检索 → 拼参考资料 → LLM 生成 → `citations` / `source_snapshots` |
| 已验证 | `answer` 中的 `[n]` 与 `citations[].index` 一一对应；**每条 `quote` 都是对应切片正文的逐字子串**（`quotes_verbatim=true`），可直接用于 GSI 前端高亮定位 |
| 已验证 | 检索无命中时直接拒答（`no_evidence=true`、`finish_reason=no_evidence`、`citations=[]`），不调模型 —— 契约明确「不能使用模型常识编造企业规则」 |
| 已验证 | `stream=true` → 400 `unsupported_stream`；同 `request_id` 同正文重试幂等（`assistant_message_id` 不变） |
| 待改进 | `citation_id` 无来源（Q3）；引号内 `[n]` 遵循度依赖提示词，实测出现过越界编号 `[9]`，已在 user 消息末尾加「共 n 条、编号只能取 1–n」缓解 —— 正式实现建议加**引用编号后校验 + 重试一次**的兜底 |
| 未覆盖 | 多轮历史（T5.3）、权限过滤（T4.3）、流式（本期契约要求 false） |

## 三、关键耗时初测与预算判断

| 环节 | 实测 | 判断 |
| --- | --- | --- |
| `#01` 解析（3 小节 Markdown） | 0.69s（fetch 0.64s / parse≈0） | 抓取占比异常高（拉的是本机文件），**必须用真实 GSI 文件地址与大文件复测**，不能作为容量依据 |
| `#03` 发布（1 批 ≤16 条切片） | 1.49s（向量化 1.45s） | 单批固定开销约 1.4s。估算 100 切片 ≈ 7 批 ≈ 10s，**需在 T3.x 用 500~2000 切片压测**，并确认 GSI 侧 HTTP 超时 |
| `#07` 检索 | 0.49s（keyword 0.01s / 向量+融合 0.74s） | 满足交互式检索；瓶颈是单次查询向量化（远程 ollama 往返约 0.7s） |
| `#14` 生成 | 16.9s；**同 prompt 另一次 34.5s** | 96% 时间在模型侧（llm 16.1s / 33.7s）。检索+拼装 < 1s |

**超时与重试的风险（需在 T1/T5 定稿）**

1. `LLM_TIMEOUT=60s` + `LLM_MAX_RETRIES=2` → **最坏 180s**，远超常规网关 60s 超时。建议：#14 单请求总预算 ≤ 45s，重试只允许 1 次且仅在超时/429 时触发，并把总预算显式传给 GSI（写进联调约定）；
2. 波动一倍说明模型侧排队不可控：`#14` 的 SLO 建议按 **p95 ≤ 30s、上限 60s** 设，超限返回可重试错误并让 GSI 决定是否重试；
3. 本期 `stream=false`，无法用「首 token 超时」早停；`max_output_tokens` 是唯一可控的截断手段（契约上限 8192），建议默认 1024~2048；
4. 向量化延迟决定了 `#03` 与 `#07` 的下限，正式实现必须：批量下发（`EMBEDDING_BATCH_SIZE`）+ 发布侧异步化/限流，避免大知识库发布时把 embedding 服务打满。

## 四、POC → 正式实现的差异清单（T1.x 起必须重做）

| POC 现状 | 正式实现要求 | 任务 |
| --- | --- | --- |
| nonce 存进程内存 | 分布式存储 + TTL（覆盖时钟窗口） | T1.1 |
| `poc_v1_*` 临时表、启动时 `CREATE TABLE IF NOT EXISTS` | `sbp_ai_*` 正式表 + Alembic 迁移 | T1.2 |
| 幂等只覆盖 3 类请求、永久有效、单表 | 三类幂等台账（解析/写入/问答）+ TTL + 冲突语义 | T1.3 |
| 无审计、无 API 日志 | 审计中间件 + `api_log` 覆盖每个 `/v1` 调用 | T1.4 |
| 召回全库、无权限过滤 | 按签名身份查 GSI 共享表计算实时权限，检索期过滤 | T4.3 |
| `pages=[]`、无 OCR/表格/页图 | 页图渲染与有效期管理 | T2.4 |
| 只有首发布 | 修订/删除四路径 + `stale_revision` 校验 | T3.2 / T3.3 |
| 无 rerank、关键词为朴素匹配 | 全文/trigram + rerank | T4.x |
| 无多轮历史、无流式 | 历史回灌（`session_id` 维度）+ 流式（契约放开后） | T5.3 |
| 错误体由 `PocApiRoute` 拼装 | 统一错误码体系 + 审计联动 | T1.2 |

## 五、契约疑点清单（Q1–Q14）

> 「当前处理」= POC 的临时口径，不代表最终实现。**待确认方**指需要 GSI 侧给出结论的责任方。

| 编号 | 疑点 | 契约原文口径 | POC 当前处理 | 建议口径 | 待确认方 | 影响任务 |
| --- | --- | --- | --- | --- | --- | --- |
| **Q1** | `authorization` 跨度 > 120s 用什么错误码 | 「`expires_at` 最长 120 秒，过期拒绝」，未给错误码 | 400 `invalid_request` | 明确为 `invalid_request`（调用方参数错误），或新增 `authorization_invalid` | GSI | T1.2 / T4.3 |
| **Q2** | `authorization` 已过期（`expires_at` < now）的错误码 | 同上，只说「过期拒绝」 | 400 `invalid_request` | 与 Q1 统一；若要求 GSI 重签，建议 `retryable=true` | GSI | T1.2 |
| **Q3** | `citation_id` 谁生成 | 「gsi 给本轮证据设置的唯一引用别名，ai 原样返回」；但 `#14` DESC 明确「gsi 不传 history 或 contexts」，请求体无证据列表 | AI 按示例生成 `c{index}` | 二选一：① 契约改为「ai 生成、gsi 仅透传展示」；② `#14` 请求新增证据/上下文下传字段 | GSI | T5.2 |
| **Q4** | 首轮会话 `session_id` 传什么 | 请求体标 `R`（必填），但语义是「ai 分配的会话 id」，首轮 GSI 不可能有值 | 允许空串，AI 生成 `ai-session-*` 并回填 | 明确「首轮传 `""` 或省略，AI 必返新 id」；并规定 `s-` 前缀保留给 GSI 旧会话 | GSI | T5.1 |
| **Q5** | `score` 的量化与用法 | 「召回相关度 0–1，不是回答正确率」，未规定算法，也未说是否可跨请求比较 | RRF 融合后按本轮最高分归一化，top 恒为 1.0 | 声明 `score` **仅用于同轮内排序**，GSI 不得用作业务阈值；若需阈值请 AI 侧另出 `min_score` 过滤 | GSI | T4.2 |
| **Q6** | `chunk_id` 是否有命名规则 | `#03` 必传、`#07/#14` 原样回传；示例形态为 `record-demo-001:1`（`{record_id}:{seq}`） | Mock 用 `chunk-1..3` | 若示例即规则，请明确「`{record_id}:{seq}` 强约束」；否则声明不透明字符串（AI 不做解析） | GSI | T3.1 / T4.1 |
| **Q7** | 「已有 `publication_id` 返回 409」的具体错误码 | 只写「返回 409，不能隐式覆盖」 | `idempotency_conflict` | 明确码值；建议与「同 ID 异正文」区分（后者是 `idempotency_conflict`，前者可考虑 `stale_revision` 或新增 `publication_exists`） | GSI | T3.2 |
| **Q8** | `#01` 受理后立刻失败怎么暴露 | 202 的 `status` 枚举只有 `queued/running/succeeded`（无 `failed`），失败只能经 `#02` 的 `failed` 暴露 | `#01` 恒回 `queued`，失败经 `#02` 的 `failed` + `error_code` | 确认 GSI 的轮询上限与重试策略（本侧解析 0.7s，大文件 + OCR 会显著变长） | 双方 | T2.1 / T2.2 |
| **Q9** | `content_hash` 的计算规则 | 「完整切片集合的内容摘要，双方按固定序列化规则计算」，规则未给出 | 只存不校验（透传 GSI 值） | 明确：算法（sha256）、序列化（字段顺序/是否 JSON 排序/是否含 `chunk_id`）、前缀（示例含 `sha256:`） | GSI | T3.1 |
| **Q10** | `metadata` 是否严格白名单 | 列出固定字段与枚举（`doc_type`/`trust`/`source_type`…），未说明多余键与非法枚举如何处理 | 整体透传 JSONB，不校验枚举 | 明确「多余键忽略 or 400」、「非法枚举忽略 or 400」，并给出 `source_type` 的取值全集（原文「支持的类型由双方确认」） | GSI | T2.3 / T3.1 |
| **Q11** | 幂等台账保留多久、过期后同 ID 异正文如何处理 | 「同 `request_id` 同正文重试返回原结果；换正文必须换 id」，未定义保留期 | 永久保留，永久 409 | 明确 TTL（建议 ≥24h）与过期后的行为（建议按新请求处理） | 双方 | T1.3 |
| **Q12** | 页图能力缺失时的 `pages` 口径 | 「没有可用页图时返回 `[]`，不能伪造图像 url」 | 返回 `[]` | 不是疑点，是**本侧能力缺口**：需明确 GSI 编辑预览在无页图时的降级形态（纯文本预览？） | 双方 | T2.4 |
| **Q13** | 模型服务不可用/超时归哪个错误码 | 错误码表有 `internal_error` / `rate_limited` / `authorization_unavailable`，未说明模型超时/5xx 的归属与 `retryable` | 500 `internal_error` | 建议：模型超时/5xx → `internal_error` 且 `retryable=true`；限流 → `rate_limited` 且带 `Retry-After` | GSI | T1.2 / T5.2 |
| **Q14** | `revision` 在首发布时如何校验 | 「新事件必须高于同一发布单元已记录值」；但 `#03` 是「首次发布」，无基线 | 不校验，原样回执 | 明确首发布是否也校验；`stale_revision` 的判据（AI 侧记录值 vs GSI 传入值）由谁判定 | 双方 | T3.2 |

> 另记一条**口径差异**（非疑点）：契约中 `tenant_id` 固定为 `gsi-default`，POC 的 Mock 脚本用 `tenant-demo`；正式实现须按 `gsi-default` 校验并透传。

## 六、移交 T1.x 的动作项

1. **T1.1**：nonce 落分布式存储（TTL ≥ 10 分钟）；签名校验抽成可复用组件，POC 的 `signature.py` 可直接作为行为基线（单测已覆盖）。
2. **T1.2**：按 Q1/Q2/Q13 起草错误码补充清单，一并与 GSI 对齐；错误体统一为 `{"error":{"code","message","retryable"}}`。
3. **T1.3**：幂等台账加 TTL（Q11），并区分「同 ID 异正文」与「publication 已存在」（Q7）。
4. **T3.x**：`content_hash` 校验（Q9）、`revision` 单调性（Q14）、大切片集合向量化压测（500~2000 条）。
5. **T4.3（最高风险）**：实时权限计算与检索期过滤 —— POC 完全未覆盖，需最早排期并预留联调用例。
6. **T5.x**：`citation_id`（Q3）、首轮 `session_id`（Q4）、引用编号兜底重试、`#14` 超时与重试预算（§三）。
7. **保留**：`app/poc/mock_client.py` 转为 T1.x 的回归脚本（`--no-chat` 可在无模型环境跑），`--reset` 与 `--record` 继续用于联调留痕。
