## 一、项目概述

### 1.1 项目背景与服务商介绍

该项目由 YIDATEC（亿达信息）为阿斯利康（AstraZeneca，简称 AZ）IT 服务台设计并交付，是一套面向企业级呼叫中心的 **AI 驱动的智能质检整体架构解决方案**。

YIDATEC 定位为 **数字化技术服务与数字化解决方案提供商**（Digital Technology Service And Digital Solution Providers），业务范围涵盖：

- 数字化咨询与解决方案
- IT/CRM 系统建设与运维
- 云服务与基础设施
- 智能客服与 AI 应用
- 业务流程外包与托管服务

### 1.2 项目定位

服务大脑 AI 质检项目并非仅是一个"用大语言模型给录音打分"的工具，而是一套 **从数据接入、智能分析、结果输出到管理闭环的完整质量管控平台**。其核心价值在于：

- 将散落在录音、工单、知识库、业务标签等多源数据整合为统一分析能力
- 用规则引擎 + 大语言模型（LLM）替代传统人工抽检的低效模式
- 从单通质检升级到团队分析、缺陷聚类、趋势发现、成长路径规划
- 形成持续改进的运营闭环

## 二、核心业务域模型

方案设计了一套完整的领域模型（Domain Model），以下为核心实体及其关系：

### 2.1 核心实体

| 实体 | 说明 | 关键属性 |
|------|------|----------|
| **CallRecord（通话记录）** | 每一次通话的基础元数据记录 | 通话时间、时长、坐席、客户、队列、项目、录音 ID |
| **TranscriptSegment（转写文本段）** | ASR 转写后的文本，按说话人分段 | 说话人角色（坐席/客户）、文本内容、时间戳、置信度 |
| **Recording（录音文件）** | 原始通话音频文件 | 文件路径、格式、时长 |
| **KnowledgeArticle（知识条目）** | 标准化的业务知识单元 | 编号、标题、适用业务场景、生效日期、版本、Owner |
| **Rule（质检规则）** | 可配置的质检判定规则 | 规则 ID、名称、分类、判定方式、评分、版本 |
| **Agent（坐席/工程师）** | 提供服务的坐席人员 | ID、姓名、所属团队、技能组、业务线 |
| **Team（团队/项目组）** | 坐席的组织归属 | 团队名称、项目经理、业务线 |
| **AuditLog（审计日志）** | 所有质检操作的追溯记录 | 操作时间、操作人、操作类型、结果变更 |

### 2.2 工单相关域模型

方案中还涉及多种工单类型的质检，对应 ServiceNow 或其他 ITSM 系统中的标准工单实体：

- **Interaction（交互记录）** — 记录每次客户交互的工单
- **Incident（事件工单）** — 记录故障、问题等异常事件
- **Request（请求工单）** — 记录服务请求、权限申请等

## 三、整体能力架构

### 3.1 总体架构层次

整个体系可视为一个端到端的处理管线（Pipeline），从数据接入到管理决策形成闭环：

```
┌─────────────────────────────────────────────────────┐
│                    数据输入层                          │
│  录音 │ ASR文本 │ 工单 │ 知识库 │ 规则库 │ 历史数据    │
├─────────────────────────────────────────────────────┤
│                    基础处理层                          │
│  转写 │ 说话人分离 │ 特征提取 │ 匹配 │ 召回 │ 清洗    │
├─────────────────────────────────────────────────────┤
│                  规则与AI评估层                         │
│  规则引擎 + LLM │ 硬性规则 │ 语义规则 │ 一致性校验    │
├─────────────────────────────────────────────────────┤
│                    结果生成层                          │
│  单通报告 │ 员工报告 │ 团队报告 │ Findings │ 趋势     │
├─────────────────────────────────────────────────────┤
│                    运营管理层                          │
│  规则配置 │ 知识维护 │ 复核 │ 申诉 │ 标注反馈闭环     │
├─────────────────────────────────────────────────────┤
│                    决策与改进层                         │
│  培训 │ 流程优化 │ 知识修订 │ 绩效 │ 辅导             │
└─────────────────────────────────────────────────────┘
```

### 3.2 各层核心能力详解

#### 第一层：数据输入层

系统需要接入以下多源数据：

| 数据类型 | 说明 | 来源 |
|----------|------|------|
| 录音文件 | 通话音频原始文件 | CTI / 电话系统 |
| ASR 转写文本 | 自动语音识别后的文本 | ASR 引擎 |
| 工单数据 | Interaction / Incident / Request 三类工单 | ITSM 系统（如 ServiceNow） |
| 客户信息 / 业务标签 | 客户 K 账号、所属 BU、业务线标签 | HR / IAM 系统 |
| 知识库内容 | 标准化的业务知识条目 | 知识管理系统 |
| 质检规则库 | 配置化的质检规则集合 | 规则管理模块 |
| 坐席与组织信息 | 坐席个人信息、团队归属、技能组 | HR / 排班系统 |
| 历史质检结果 | 过往的质检评分和标签 | 质检数据库 |
| 投诉 / 升级 / 复联数据 | 服务结果反馈数据 | ITSM / 投诉系统 |

#### 第二层：基础处理层

对原始数据进行以下预处理操作：

- **录音转文字（ASR）**：将通话音频转为结构化文本
- **说话人分离（Speaker Diarization）**：区分客户与坐席的讲话段落
- **音频特征提取**：检测静音段、打断事件、语速变化、情绪声学特征等
- **工单与通话匹配**：将每通通话与对应的 Interaction / Incident / Request 工单关联
- **知识召回（Knowledge Retrieval）**：基于通话主题和客户问题，从知识库中检索相关条目
- **数据清洗与标准化**：统一数据格式、去噪、补全缺失字段

#### 第三层：规则与 AI 评估层

这是系统的核心智能层，采用 **规则引擎 + 大语言模型（LLM）** 的混合判定架构：

**强规则类判定（传统规则引擎）**
- 是否使用标准开场白
- 是否完成身份核验
- 是否触发敏感词 / 禁用话术
- 是否出现长时间静音
- 是否超出规定通话时长
- 是否按规定创建工单
- 是否选择正确工单分类

**弱规则 / 语义类判定（规则模板 + LLM 辅助）**
- 是否准确理解客户问题
- 是否有效安抚客户情绪
- 是否给出完整解决方案
- 是否存在推诿行为
- 是否体现同理心
- 是否符合服务规范

**知识一致性判定（知识召回 + LLM 比对）**
- 坐席回答是否与知识库一致
- 是否存在错误解释
- 是否使用了过期信息
- 是否漏答关键信息点

**工单一致性判定（通话 vs 工单比对）**
- 通话内容与工单记录是否一致
- 是否存在少记、错记、误分类
- Caller / Category / Subcategory 是否正确

**风险识别**
- 投诉风险评估
- 合规风险识别
- 客户流失风险
- 升级风险判断

#### 第四层：结果生成层

对每一通通话，系统自动生成以下多层级输出：

| 输出类型 | 内容 | 面向角色 |
|----------|------|----------|
| 单通质检结果 | 总分、维度分、缺陷标签、风险标签、证据片段 | 质检员、主管、坐席 |
| 单员工分析报告 | 周期趋势、高频缺陷与亮点、与团队对比 | 员工本人、班组长 |
| 团队 / 项目汇总报告 | 整体得分、缺陷分布、风险分布、排名对比 | 项目经理、运营经理 |
| Findings 与缺陷聚类 | 问题描述、影响范围、根因、建议动作 | 质量负责人 |
| 改进建议与培训建议 | 针对性的改进方向和培训计划 | 培训团队、管理层 |
| 趋势看板与成长路径 | 覆盖率、合规率、CSAT 变化趋势 | 管理层 |

#### 第五层：运营管理层

支撑日常运营的后台功能：

- **规则配置后台**：表单式 + 模板式规则配置，非 AI 人员可维护
- **知识维护后台**：业务单元视角的知识条目增删改查、版本管理
- **质检复核机制**：对 AI 判定结果进行人工抽样复核，并反馈修正
- **申诉与修正流程**：坐席对质检结果有异议时的申诉流程
- **标注与反馈闭环**：人工标注数据用于模型持续优化
- **模型持续优化机制**：Prompt 模板管理、评估集管理、模型效果监控、错误案例回灌

#### 第六层：决策与改进层

将质检结果转化为管理动作：

- 基于缺陷数据制定培训计划
- 基于根因分析驱动流程优化
- 基于知识点不匹配问题推动知识库修订
- 基于项目问题排名推动运营改进
- 基于成长路径数据进行绩效管理与辅导

## 四、LLM 在体系中的角色

### 4.1 LLM 的嵌入点

LLM 不是替代所有模块的"万能钥匙"，而是精准嵌入到关键节点中：

| 嵌入节点 | 具体职责 |
|----------|----------|
| 对话摘要 | 自动生成通话流程摘要 |
| 客户意图识别 | 判断客户来电的真实目的和意图 |
| 服务过程理解 | 理解坐席与客户的完整交互过程 |
| 复杂语义规则判断 | 处理传统规则引擎无法覆盖的语义判断场景 |
| 知识一致性校验 | 将坐席回答与知识库标准答案进行语义比对 |
| 根因归纳 | 从多条缺陷记录中归纳根本原因 |
| 缺陷聚类 | 将大量零散缺陷自动聚合为可管理的发现 |
| 报告自动生成 | 自动生成多层级质检报告 |
| 员工反馈建议生成 | 针对员工的具体缺陷生成改进建议 |
| 项目 Findings 提炼 | 从团队级数据中提炼管理发现 |

### 4.2 LLM 的边界

以下场景不适合由 LLM 单独承担，应使用传统规则引擎或算法：

- 明确格式校验（如工单字段非空校验）
- 固定流程校验（如开场白、结束语的精确匹配）
- 严格合规项判定（如身份验证是否完成）
- 可量化的音频特征判断（如静音超过 X 秒）
- 强依赖精确条件的打分（如某项未做直接扣分）

## 五、质检输出体系

### 5.1 单通质检示例（Dashboard 视图）

方案中展示了一个质检执行看板的示例，包含以下关键信息区域：

- **通话基础信息区**：通话时间、坐席姓名、坐席 ID、业务类型、通话时长
- **规则命中概况**：已判定规则数、命中/未命中分布
- **各维度得分**：服务规范、业务准确性、问题解决等子维度分数
- **总分与趋势对比**：当前得分 vs 历史趋势
- **关键缺陷列表**：命中的不合格规则详情
- **Top3 缺陷类型**：按频次排序的高频缺陷
- **Top3 亮点**：按频次排序的高频优秀表现
- **风险标签**：合规风险、投诉风险、升级风险
- **证据片段展示**：关键对话片段的原文引用
- **改进建议**：针对性的改善方向
- **知识一致性对比**：标准答案 vs 坐席回答 vs 差异说明
- **工单一致性对比**：通话内容 vs 工单记录 vs 差异说明

### 5.2 数据看板（Analytics Dashboard）

方案中展示了一个分析看板的示例结构和关键指标：

- **质检覆盖率趋势**：目标 > 90%
- **CSAT 客户满意度变化**：目标 > 85%（显示 +7.8 的趋势改善和 18% 的提升）
- **合规率变化**：目标 > 70%（显示 +12.6% 提升）
- **一次性解决率（FCR）趋势**：目标 > 80%
- **缺陷发生率趋势**：目标 < 8%
- **高频缺陷类型排名 Top10**：显示各类缺陷的占比分布
- **员工得分分布**：不同分数段的员工分布比例
- **团队间对比**：各团队的得分和覆盖率对比
- **知识库不匹配Top问题**：哪些知识条目频繁引发错误回答

## 六、技术栈概要

方案提及以下技术选型：

### 6.1 核心 AI 能力

- **LLM（大语言模型）**：用于语义分析、对话理解、报告生成等高级认知任务
- **ASR（自动语音识别）**：录音转文字
- **说话人分离（Speaker Diarization）**：区分客户与坐席
- **RAG（检索增强生成）**：知识召回 + LLM 生成
- **规则引擎**：处理硬性规则和结构化校验

### 6.2 数据存储

- **PostgreSQL**：关系型数据库，存储质检结果、规则配置、工单数据等

### 6.3 Prompt 工程与管理

- **Prompt 模板管理**：统一的 Prompt 版本控制和模板库
- **评估集管理**：用于模型效果评估的标注数据集
- **错误案例回灌**：将人工修正的案例重新纳入训练/优化流程

## 七、量化绩效指标

方案中明确的量化目标：

### 7.1 质检效能指标

| 指标 | 目标值 |
|------|--------|
| 质检覆盖率 | > 90% |
| 人工复核比例 | < 10% |
| 知识一致性准确率 | > 80% |
| 客户满意度（CSAT） | > 85% |
| 合规率 | > 70% |
| 一次性解决率（FCR） | > 80% |
| 关键缺陷发生率 | < 8% |
| 员工服务评分达标率 | > 90% |
| 工单规范性达标率 | > 60% |
| 月度一次性解决率（Monthly FCR） | > 2（含义为每坐席每月 FCR 达标次数） |

### 7.2 运营效率指标

- 质检周期从通话结束到结果输出显著缩短
- 质检覆盖率从传统人工抽检的不到 30% 提升到全量或接近全量
- 跨质检员标准一致性显著提升
