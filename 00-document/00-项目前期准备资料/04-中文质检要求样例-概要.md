# 中文质检要求 - 样例 — 概要

> 来源：`04-中文质检要求样例-原件.docx`（原文件名「中文质检要求 - 样例.docx」）

该文件包含四类质检规则库的完整规则样例，共计 60 条规则，覆盖电话质检、Interaction 工单质检、Incident 工单质检、Request 工单质检。

## 一、电话质检规则库（TEL-001 ~ TEL-016）

共 16 条电话质检规则，涵盖坐席通话全流程：

### 1.1 通话规范类（7 条）
- **TEL-001** 接听前耳机与通话音质要求
- **TEL-002** 标准开场语使用（\"欢迎致电阿斯利康IT服务台，我是XXX，请问您K账号多少\"）
- **TEL-009** 标准结束语使用（\"如果没有其他问题，工单就帮您关闭了\"）
- **TEL-014** 普通话使用要求
- **TEL-015** 转接正确性要求
- **TEL-016** 静音前告知要求（\"抱歉同事，我需要帮您确认一下，电话会处于静音状态...\"）

### 1.2 身份验证类（3 条）
- **TEL-003** 身份验证前置要求（提供技术支持前必须验证）
- **TEL-004** 身份验证方式范围（Teams/邮件/iPad 序列号/直线经理，四选一）
- **TEL-005** 身份验证未通过不得提供支持（强制合规项）

### 1.3 服务态度类（3 条）
- **TEL-010** 服务态度合规要求（礼貌、积极、友好、专业）
- **TEL-011** 不良情绪禁止要求（呵斥、嘲笑、辱骂、不耐烦等属于负向强判）
- **TEL-012** 有效解释要求（用户未理解时需补充解释，不得仅机械重复）

### 1.4 交互技巧类（2 条）
- **TEL-006** 同日重复来电确认要求
- **TEL-013** 打断用户前礼貌提示要求（如\"非常抱歉，打断您一下\"）

### 1.5 服务闭环类（2 条）
- **TEL-007** 结束前确认其他需求
- **TEL-008** 服务评价引导要求（\"麻烦您稍后点击邮件中的笑脸提交评价\"）

## 二、Interaction 工单质检规则库（INT-001 ~ INT-011）

共 11 条 Interaction 工单规则：

### 2.1 工单创建与一致性（4 条）
- **INT-001** 唯一创建要求（一通电话仅一个 Interaction）
- **INT-005** Type 一致性（Phone/Chat/Email，严格枚举）
- **INT-006** Caller 一致性（关键归属字段，不可错挂/代挂）

### 2.2 Short Description 规范（3 条）
- **INT-002** 必须包含 CTI 信息
- **INT-003** 必须包含问题概括（能体现核心问题）
- **INT-004** 字数要求（问题描述不超过 6 字）

### 2.3 状态管理（2 条）
- **INT-007** closed abandon 状态原因范围（5 个允许值：Wrong Number / Hung up / User Abandoned / Junk Email / Insufficient Information to Progress）
- **INT-008** closed complete 状态下不允许其他 State Reason（严格互斥）

### 2.4 Work Notes 记录（2 条）
- **INT-009** 必须记录身份验证方式
- **INT-010** 必须记录录音 ID（格式如：a06edd99-1e80-4e91-96ae-a8f271b42318）
- **INT-011** 身份验证记录标准格式（4 种中英双语标准模板）

## 三、Incident 工单质检规则库（INC-001 ~ INC-016）

共 16 条 Incident（事件）工单规则：

### 3.1 归属与分类（3 条）
- **INC-001** Caller 一致性
- **INC-002** Category 一致性
- **INC-003** Subcategory 一致性

### 3.2 Short Description（3 条）
- **INC-005** 必须包含 CTI 信息
- **INC-006** 必须包含问题概括
- **INC-007** 禁用词：不允许出现\"How to\"、\"如何使用\"等字样

### 3.3 Description 模板（6 条）
- **INC-008** 模板类型要求（派单/自开自关/邮件，三选一）
- **INC-009** 通用字段 Caller PRID 必填
- **INC-010** 派单模板联系电话必填
- **INC-011** 邮件模板：收件与回复时间间隔 ≤ 15 分钟
- **INC-012** 邮件模板：时间真实性校验

### 3.4 优先级与关闭（3 条）
- **INC-004** 非母单 Priority 不高于 3 级
- **INC-013** 自开自关工单需在 60 分钟内关闭（超时标记为 Miss FCR）
- **INC-015** Resolution Code 严格枚举（8 个允许值）

### 3.5 其他（2 条）
- **INC-014** Service 字段与实际系统一致性
- **INC-016** Resolution Notes 模板要求（Troubleshooting Steps 1/2/3 + 用户同意关单）

## 四、Request 工单质检规则库（REQ-001 ~ REQ-013）

共 13 条 Request（请求）工单规则，结构与 Incident 类似但略有差异：

### 与 Incident 相同/相似的部分
- Caller/Category/Subcategory 一致性、Priority 不高于 3 级、Short Description 含 CTI、Description 模板要求、字段必填、邮件模板时间等

### 对 Request 的特殊要求
- **REQ-007** Short Description 禁用词：不允许出现\"无法\"\"不能\"\"报错\"等故障类字样（因 Request 是需求类，不是故障类）
- **REQ-013** 特殊 Service Catalog 限制：APAC ONSITE、NCEP CRM/EVENT、WECOM、APAC PRINTER、ACTIVE DIRECTORY、EXUEHUI WECHAT 等 7 个 Service 不得使用 General Request 模板

## 五、规则设计特征总结

所有规则均采用统一的字段结构：
- 规则名称 → 适用范围 → 判定条件 → 合格标准 → 不合格判定 → 备注

这种结构化表达方式是需求说明书中提倡的\"配置化规则体系\"的良好范本：
1. 每条规则独立、可量化、有明确合格/不合格边界
2. 硬性规则（如枚举校验、关键词匹配）与语义规则（如态度判断）明确分层
3. 备注中指明判定方式（精确匹配/语义辅助/人工复核），为后续技术实现提供指导
