# 知识平台与 AI 服务接口手册（v3）
> **GSI × AI 接口参考 · v3** | AI 团队对接版 | OpenAPI 3.0.3 | 页面日期 2026-10-28
> AI 团队实现、GSI 后端调用的 21 个服务接口（19 个路径），涵盖文档解析、正式知识切片、检索、会话、回答与重复治理。使用 HMAC-SHA256 认证，共享 service_brain PostgreSQL 数据库，AI 在独立 schema 管理切片与 pgvector 向量。本文定义对接契约，不作为服务上线或验收证明。

> **阅读方式**：Swagger 风格的接口参考。展开接口 → 查看请求参数 → 查看响应参数 → 复制完整 JSON 示例。本手册由 v3 HTML 版（`01-知识平台与AI接口对接说明-v3.html`）转换生成，内容与页面内嵌 OpenAPI JSON 同源；原 HTML 的“下载 OpenAPI JSON”可导入 Swagger Editor / Apifox。
>
> **字段阅读约定**：字段路径中的 `[]` 表示数组元素；“父级存在时必填”表示父对象提供后必须传入该字段；文档中的域名、ID、时间和摘要均为示例，不能直接用于生产请求。

## 版本变更说明（v3 相对 v2.1）

> 基线：v2.1（20 个接口 / 18 个路径，其 HTML 与 MD 已随 v3 发布删除）。v3 页面内嵌 OpenAPI 的 `info.title`、`info.version` 仍为 **2.1.0**，侧栏仍写“v2.1 · 20 个接口”，但实际契约已变为 **21 个接口 / 19 个路径**。正式发布前建议 GSI 同步修订版本号与计数。

### 1. 新增接口（1 个）

| 编号 | 接口 | 方法 | 路径 | 分组 |
| --- | --- | --- | --- | --- |
| D06 | 单篇知识切片查重 | POST | `/v1/knowledge/duplicates/chunk-check` | 重复治理 |

用途：对单篇草稿/已发布且解析成功的知识做只读查重，按切片与授权范围内其他文档比较，返回命中正文、相似度及重复切片占比；不合并、不审批、不更新索引。

### 2. 契约语义变化（影响实现）

1. **切片 ID 归属反转：AI 生成并维护 `chunk_id`，GSI 只引用。**
   - `03.1 新增已批准切片集合`（POST `/v1/knowledge/entries`）与 `03.3 修改已批准切片集合`（PUT）的请求 `chunks[].chunk_id` 由**必填改为可选**：引用或修改已有切片时传 AI 返回的原 ID；新增切片省略，由 AI 分配。
   - `03.2`、`04`、`07`、`12` 等响应中的 `chunk_id` 说明统一为“AI 生成并维护的正式切片 ID，GSI 查询后原样引用，不自行生成；需结合知识、发布单元和快照校验归属”；示例由 `record-demo-001:1` 改为 `ai-chunk-001`。
   - 写入成功后 GSI 通过 `03.2` 查询确认 ID；同请求重试不得重复分配。

2. **重复治理草稿切片增加 `seq` 定位。**
   - D01–D04 请求中 `scope.drafts[].chunks[]` 新增**必填** `seq`（冻结草稿内从 1 开始的唯一顺序），`chunk_id` 改为可选；`candidate.chunks[]` 同样调整。
   - D01 响应 `matches[]`、D02/D03 响应 `groups[].items[]` / `group.items[]` 新增可选 `source_seq`：未入库草稿命中时必返，等于输入 `drafts[].chunks[].seq`；此时 `chunk_id` 是 AI 分配的临时检测 ID，**仅限本次检测，不能写回正式库**。
   - D06 直接使用 `source_seq` / `target_seq` 定位切片对，不使用 `chunk_id`。

3. **新增“切片存储与 ID 归属”章节**（本手册第二节），明确 AI 保存正式切片、正文与向量；GSI 仅保存本地修订单元与 AI 切片 ID 的引用映射，以及草稿和审批审计资料。

### 3. 文档结构修复与调整

- v2 HTML 在“提供给 AI 的指定共享表”处约有 3 KB 二进制损坏，导致 `sbp_km_doc` 及 FAQ 相关表等丢失；v3 该章节完整，本手册已恢复 **14 行共享表清单**（含 `sbp_faq_publication`、`sbp_faq_record`、`sbp_faq`、`sbp_km_ai_delivery`、编辑态受众表）及完整 SQL 示例。
- 章节编号顺延：原“二、知识修订”起各节后移一位；新增“二、切片存储与 ID 归属”。
- 侧栏新增 D06 入口；接口卡片区末尾追加 D06 手写卡片。

### 4. 未变化部分

- 原有 20 个接口的路径、方法、请求头、HMAC 签名算法、错误码与公共鉴权说明均未变化。
- OpenAPI 组件 Schema（`Snapshot`、`Authorization`、`IndexChunk`、`ParseResult`、`Citation`、`ChatMessage`、`Completion`、`Error`、`KnowledgeMetadata`、`KnowledgeEntry`）无结构增删，仅 `chunk_id` 字段描述与示例更新。

### 5. 待 GSI 确认

- `info.version` 仍为 `2.1.0`，页面计数仍为 20；是否发布为正式 `3.0.0` / 21 个接口需 GSI 确认。
- D06 未进入页面“重复治理 · AI 对接说明”的流程段落（该段仍只描述 D01–D05），是否补充由 GSI 决定。

## 一、服务职责与接入约定

本文面向 AI 服务开发与联调人员。全部 21 个接口（19 个路径）由 AI 团队提供，GSI 后端签名调用；浏览器不直接调用 AI 服务。AI 返回裸 JSON，不增加 GSI 的 code / msg / data 包装。

**AI 服务负责：**文档解析、FAQ 提取、正式切片存储、Embedding 向量生成、pgvector 存储与检索、按权限检索知识、回答生成、用户会话与对话历史、重复检测及合并预览。

**GSI 负责：**可信用户身份、知识元数据、草稿、审批、发布范围与生效时间、治理处置、调用签名以及返回来源的权限复核。点赞点踩由 GSI 保存，AI 保持会话和消息标识稳定。

**数据存储：**双方共用 service_brain PostgreSQL 数据库。AI 使用独立数据库账号，在 ai_knowledge schema 管理正文、向量、会话、消息和幂等记录；pgvector 用于保存和检索 Embedding 模型生成的向量。GSI 业务表按下文指定字段只读开放。

**接入地址：**以 AI 服务 Base URL 拼接下方 /v1 路径。联调地址、生产地址、client_id 和签名密钥通过双方约定的配置渠道提供。文档中的域名、ID、时间和摘要为示例，不能直接用于生产请求。

**参数阅读：**字段路径中的 [] 表示数组元素；“父级存在时必填”表示父对象提供后必须传入该字段。接口卡片分别提供请求参数、响应参数、错误响应和可复制 JSON 示例。

**一致性：**知识 record_id、version_id、revision 标识批准快照和操作顺序；会话使用 request_id 幂等与服务端串行处理。正式写入返回最终完成回执，同请求 ID 的重试必须保持正文一致。

## 二、切片存储与 ID 归属

AI保存正式切片、正文及向量，并生成和维护chunk_id。GSI通过接口查询正式切片，仅保存本地修订单元与AI切片ID的引用映射，以及草稿和审批审计资料。

修改已有切片传回原ID；新增切片不传ID。GSI在写入成功后查询03.2确认ID，同请求重试不重复分配。不同发布单元的引用分别保存，删除单片通过全量修改移除该项，不删除整篇知识。

未入库草稿用于重复检测时，以seq定位冻结输入；AI返回的临时检测ID仅用于本次治理，不作为正式切片ID。

## 三、知识修订：AI 读取，GSI 审批，批准后写回

1. 进入修订页面，GSI 校验维护权限，通过 03.2 精确读取 publication_id + record_id 的 AI 切片，并读取全部分页，保存修订基线。
2. 新增、修改、删除切片先保存在 GSI 修订草稿，保留原文、修改后全文和变更说明。前端不能直接调用 AI 写接口。
3. 提交现有整单审批或切片修订审批。待审、驳回、退回、撤回时都不修改 AI 正式切片；重新打开页面优先恢复 GSI 草稿，不能被 AI 原文覆盖。
4. 相应审批最终通过后，GSI 后端构造完整目标切片集合。首次发布调用 03.1；修订调用 03.3；批准删除整个目标集合调用 03.4。删除单片通过 03.3 提交移除该片后的完整集合，不额外增加单片接口。
5. 计划发布需等到计划时点才对外生效；部分受众通过只更新已通过的发布单元。AI 不根据 metadata.audience 自动扩散发布范围。
6. AI 写入新快照并完成向量化后返回最终回执，GSI 再切换对应发布指针。AI 可同时保留旧、新快照，权限查询只认可 GSI 当前指向的快照；切换前继续使用旧内容。
7. 失败时保留旧生效快照，以原 request_id 和完全相同的正文重试。批准内容若改变必须重新审批并使用新请求 ID。基线冲突返回 409，不能静默覆盖。

读接口适用“知识维护权限”（如本人、归属团队、审批处理权限），回答接口适用“消费权限”（生效发布 + 受众团队 + 不可见排除）。二者不能混用。审批和发布状态仍由 GSI 管理；AI 保存检索内容、向量和快照，不写 GSI 审批业务表。

**发布一致性：**AI 写入成功、GSI 切换失败时，旧发布继续有效，新快照不参与回答；重试回执后继续切换。GSI 撤销发布后，即使 AI 暂时未删数据，也必须立即停止召回。DELETE 保留幂等墓碑，迟到 CREATE / UPDATE 不得复活已删除数据。空集合不能作为正常发布；删除最后一片需要走批准删除及撤销发布流程。

**写入前提：**GSI 在审批通过且满足生效条件后调用写入接口。AI 验证服务签名、资源归属与修订顺序，不接收审批信息、不查询 GSI 审批记录。审批单及执行事件由 GSI 内部通过 request_id 关联。

## 四、提供给 AI 的指定共享表与权限

数据库：`service_brain`。实际部署 schema / search_path 在开通账号时确认。AI 使用独立账号，读取所需字段；只在自有 `ai_knowledge` schema 写入切片、pgvector 向量、会话和消息。数据库账号与只读授权由数据库管理员配置。

| 表名 | 用途 | 指定字段 | 关联及注意事项 |
| --- | --- | --- | --- |
| sbp_sys_org | 组织架构 | id, parent_id, name, code, type, category, source_org_id, status, deleted | parent_id → id；category 区分 admin / business，source_org_id 为业务镜像关联行政组织。组织上下级不自动继承知识权限。 |
| sbp_sys_org_member | 组织成员 | org_id, user_id | org_id → sbp_sys_org.id；user_id → sbp_sys_user.id。仅提供组织归属，不代替受众团队成员关系。 |
| sbp_sys_audience_team | 受众团队 | id, group_code, group_name, audience_team, status, deleted | 仅 status=1 且 deleted=0 有效。当前 userTeams 同时兼容编码、名称及 audience_team；新写入使用 group_code。 |
| sbp_sys_audience_team_member | 受众团队成员 | team_id, user_id | team_id → sbp_sys_audience_team.id；以签名 user_id 查询，不使用姓名。 |

| sbp_km_doc | 文档主记录 | id, knowledge_no, status, deleted | deleted=0；Archived / Unpublished 拒绝。修订审批中如果旧发布关系仍有效，旧内容可继续使用，不能简单只取主表 status=Published。 |
| sbp_faq_publication | FAQ 按团队生效关系 | id, faq_id, team, record_id, access_rules_json, index_status, updated_at | faq_id → sbp_faq.id；record_id → sbp_faq_record.id；授权优先使用 access_rules_json，缺省才读 record.snapshot_json。 |
| sbp_faq_record | FAQ 生效快照 | id, faq_id, stage, status, snapshot_json | 只能使用当前发布指向内容。授权 JSON 必须含 invisibleTeams 数组；缺失、解析失败时拒绝，不能拿编辑表补权限。 |
| sbp_faq | FAQ 主记录 | id, faq_no, status, deleted | deleted=0；Archived / Unpublished 拒绝；结合发布单元判断，不用编辑中正文回答。 |

| sbp_km_doc_audience / sbp_km_doc_invisible_team | 文档编辑态受众（说明用，不作生效授权） | 前表：doc_id, dim, value；后表：doc_id, team | 用于 GSI 编辑与审批，修改可能尚未生效；AI 不用它们替代 publication + record 的权限。 |
| sbp_faq_audience | FAQ 编辑态受众（说明用） | faq_id, dim, value | 同样不代表已发布受众；无须为知识回答开放此表。 |

**不建立不存在的关联：**受众团队表当前没有 org_id，组织表也没有指向受众团队的外键。两者通过同一个 user_id 的成员关系供查询，不能按同名团队推导授权。上级组织、负责人或管理员角色都不能自动获得所有问答知识；当前消费侧仍以受众成员为准。

**最小开通范围：**组织及成员 2 表、受众及成员 2 表、用户与职级指定列 2 表、文档 / FAQ 的主记录 / 发布 / 快照各 3 表，共 12 张核心表；投递表仅用于对账。编辑态受众表只在文档中说明，无须为 AI 知识回答授权。可按上述字段建立只读视图再授权，视图名与 DDL 由双方确认。

### 成员和候选数据查询示例

```sql
-- 基于工程 KmDocMapper.userTeams 的只读成员查询；$1 为可信用户数字 ID。
-- 这是成员标识查询，不是完整授权 SQL。所有业务查询必须参数绑定。
SELECT DISTINCT x.team_key
FROM sbp_sys_audience_team t
JOIN sbp_sys_audience_team_member m ON m.team_id = t.id
CROSS JOIN LATERAL (VALUES (t.group_code), (t.group_name), (t.audience_team)) x(team_key)
WHERE m.user_id = $1 AND t.deleted = 0 AND t.status = '1'
  AND NULLIF(BTRIM(x.team_key), '') IS NOT NULL;

-- 文档候选：$1 为上面查询得到的 text[]；结果必须继续执行下方 JSON 与索引校验。
SELECT p.id AS publication_id, p.doc_id AS resource_id, p.record_id,
       p.team, d.knowledge_no, r.snapshot_json
FROM sbp_km_doc_publication p
JOIN sbp_km_doc d ON d.id = p.doc_id
JOIN sbp_km_doc_record r ON r.id = p.record_id AND r.doc_id = d.id
WHERE d.deleted = 0 AND d.status NOT IN ('Archived','Unpublished')
  AND p.team = ANY($1::text[]);

-- FAQ 候选：不得跳过 access_rules_json 的优先级。
SELECT p.id AS publication_id, p.faq_id AS resource_id, p.record_id,
       p.team, f.faq_no,
       COALESCE(NULLIF(BTRIM(p.access_rules_json), ''), r.snapshot_json) AS effective_rules
FROM sbp_faq_publication p
JOIN sbp_faq f ON f.id = p.faq_id
JOIN sbp_faq_record r ON r.id = p.record_id AND r.faq_id = f.id
WHERE f.deleted = 0 AND f.status NOT IN ('Archived','Unpublished')
  AND p.team = ANY($1::text[]);
```

### 候选数据必须继续执行的判断

1. 验证签名、租户和用户身份；当前 GSI 表没有 tenant_id，当前仅配置允许的 gsi-default 使用这些表。未来多租户必须增加真实租户隔离，不能只靠传参。
2. 取得有效受众团队标识；空集合立即返回空命中，绝不表示全库。行政 / 业务组织只用于组织上下文，不递归扩权。
3. 匹配各发布单元 team，读取其 record_id 指向的生效快照；拒绝逻辑删除、已归档或已下架资源。
4. 解析生效 JSON，invisibleTeams 命中任一用户团队即拒绝，排除优先；expireAt 按 Asia/Shanghai 日期判断，早于当天拒绝。FAQ 优先 access_rules_json，缺少 invisibleTeams 或 JSON 无效拒绝；不能使用编辑草稿推断权限。
5. 与 AI 本地索引的 resource_type / resource_id / publication_id / record_id / version_id / revision 对齐，并要求索引就绪。全文和向量检索都限定在这些候选内，不能把未授权内容交给模型。
6. 本轮答案及历史摘要的所有知识依赖都要可访问。撤权后的历史正文、引用、派生标题不能通过会话查询、幂等回放、13 结果查询或下一轮上下文泄漏。提交回答前 AI 再检查一次，GSI 展示前复核 source_snapshots。

权限表不可读取时返回 503 AUTHORIZATION_UNAVAILABLE，不能退化为全库检索；用户无权或无可用证据属于正常空结果。团队调整、停用、撤权必须在下一请求生效，不能长期缓存用户权限。保留当前 group_code / group_name / audience_team 的兼容匹配，但新数据使用唯一编码；部署前检查重名与冲突。

SQL 示例仅用于筛选候选，必须配合上述权限检查；所有业务查询使用参数绑定。

## 五、公共请求头与签名

所有接口均使用 HMAC-SHA256；不传 Bearer Token，不把密钥发送给 AI。JSON 正文使用 UTF-8，`Content-Type: application/json; charset=utf-8`。GET 没有正文。

| 字段路径 | 类型 | 是否必需 | 中文说明 / 约束 | 示例值 |
| --- | --- | --- | --- | --- |
| X-AI-Signature-Version | string | 必填 / 必返 | 固定 v1。 | "v1" |
| X-AI-Client-Id | string | 必填 / 必返 | 固定 gsi-service，AI 通过该标识选择共享密钥。 | "gsi-service" |
| X-AI-Timestamp | string | 必填 / 必返 | 13 位 Unix 毫秒，允许前后 5 分钟；示例时间不能直接用于在线调用。 | "1800000000000" |
| X-AI-Nonce | string | 必填 / 必返 | 每次 HTTP 请求新生成的 UUID；16–128 位字母、数字、下划线或连字符。 | "11111111-2222-4333-8444-555555555555" |
| X-AI-Signature | string | 必填 / 必返 | 原始正文签名，64 位小写十六进制 HMAC-SHA256；不是直接发送密钥。 | "<运行时计算的签名>" |

### 签名原文：七行，用 LF 连接，末尾没有换行

```text
v1
gsi-service
{X-AI-Timestamp}
{X-AI-Nonce}
{大写 HTTP 方法}
{原始路径及可选查询字符串}
{实际请求正文原始字节的 SHA-256 小写十六进制摘要}
```

`X-AI-Signature = HMAC-SHA256(共享密钥, 上述 UTF-8 原文)`，输出 64 位小写十六进制。无正文对空字节序列求 SHA-256。AI 必须在解析 JSON 前验签，不能排序字段或重序列化。

验签通过后原子登记 client_id + nonce，保留至 timestamp + 5 分钟之后。生产多实例及重启期间必须共享持久防重放记录。业务幂等 ID 重试保持不变，时间戳、nonce 和签名每次重新生成。

## 七、接口详情

### 解析

#### 01 提交文档 / FAQ 解析任务

`POST /v1/parse/jobs`

录入知识或从文档解析 FAQ 时调用。AI 接受任务后返回 202，GSI 随后轮询任务结果；不需要取消接口。相同 job_id + 相同正文重试返回原任务。FAQ 由 prompt_text 指定提取问题与答案，不另设 FAQ 解析接口。 新增 metadata，涵盖新增页面字段。解析产物为待确认草稿，AI 不得自动写入正式检索库；提示词和模型仍传正文及模型键。FAQ 从文档解析同样携带已填写的公共元数据。 resource_type=document 时 prompt_text、model_key 可选；resource_type=faq 时两项必填。提供的值必须包含非空白字符；FAQ 缺失任一字段或传入空值返回 HTTP 400 INVALID_REQUEST。

#### 03.3 修改已批准切片集合

`PUT /v1/knowledge/entries/{publication_id}`

  }

**HTTP 401 · Unauthorized：缺少有效的认证凭据；本协议包括签名无效、签名时间过期或 nonce 重放。**

**错误响应 JSON 示例**

```json
{
  "error": {
    "code": "UNAUTHORIZED",
    "message": "服务签名认证失败，请检查签名、时间戳和 nonce。",
    "retryable": false
  }
}
```

**HTTP 403 · Forbidden：服务理解请求但拒绝执行；本协议用于认证后权限不足或授权范围失效。**

**错误响应 JSON 示例**

```json
{
  "request_id": "req-20261029-001",
  "error": {
    "code": "CONTEXT_OUT_OF_SCOPE",
    "message": "当前身份无权访问请求范围内的资源。",
    "retryable": false
  }
}
```

**HTTP 404 · Not Found：目标资源不存在，或服务不愿披露其存在；可用于隐藏他人会话或检测结果。**

**错误响应 JSON 示例**

```json
{
  "request_id": "req-20261029-001",
  "error": {
    "code": "NOT_FOUND",
    "message": "请求的资源不存在或不可访问。",

  }
}
```

#### D01 保存前重复检查

## 八、业务错误码与处理方式

按以下 6 类处理，表中列出常见 error.code；具体原因查看 error.message。

| 分类 | 常见业务码 | HTTP | 处理方式 |
| --- | --- | --- | --- |
| 参数错误 | INVALID_REQUEST | 400 | 修正参数后重新提交。 |
| 认证失败 | UNAUTHORIZED | 401 | 检查签名、时间戳和 nonce。 |
| 无访问权限 | CONTEXT_OUT_OF_SCOPE | 403 | 重新确认用户权限，不直接重试。 |
| 资源不存在 | NOT_FOUND | 404 | 确认资源 ID 或刷新列表。 |
| 状态冲突 | IDEMPOTENCY_CONFLICT / STALE_REVISION | 409 | 核对请求 ID 与正文，或读取最新版本。 |
| 服务异常 | INTERNAL_ERROR | 500 | 根据 retryable 判断是否重试。 |

仅当 retryable=true 时自动重试；保留原请求 ID 和正文，重新签名。其他细分业务码按对应 HTTP 类别和 message 处理。任务查询返回的 failed 表示原任务失败，不代表查询请求失败。

## 九、重复治理 · AI 对接说明

D01 保存前查重，D02 查询重复分组，D03 获取详情与证据，D04 生成合并预览，D05 停用知识，D06 单篇知识切片查重（v3 新增）。参数表、请求及响应示例见对应接口卡片。

**调用流程：**GSI 生成操作者可管理的知识范围 → D01 保存前提示或 D02 查询分组 → D03 查看来源及全文 → D04 生成预览 → GSI 冻结方案并完成工作台审批 → 批准后执行正式修改、删除或停用。审批中、驳回、撤销均不写 AI 正式内容；AI 不提供审批接口。来源内容变化后必须重新检测确认。

| 批准后的处置 | 调用 AI | 约束 |
| --- | --- | --- |
| 修改主 FAQ / 移除重复切片 | 03.3 PUT /v1/knowledge/entries/{publication_id} | 提交生效的完整切片集合、元数据和 base_record_id；单片删除不能删除整篇知识。 |
| 废弃 / 下架整篇知识 | D05 POST /v1/knowledge/entries/{publication_id}/deactivate | 停止检索与回答引用；保留内容供审计。 |
| 删除整篇知识 | 03.4 DELETE /v1/knowledge/entries/{publication_id} | 删除指定快照正文与向量；GSI 保存业务审计。 |

GSI 内部通过 request_id 关联执行事件，不传递审批单信息。多个团队发布单元分别处理。GSI 持久化执行事件，AI 必须返回最终成功回执；响应丢失按相同 request_id、相同正文重试，并重新生成签名时间戳与 nonce。不新增知识业务状态，失败重试进度保存在治理任务中。

**权限与数据：**scope 是知识管理范围，不能用问答受众范围代替。AI 只比较其中明确的 resource_type、resource_id、record_id、content_hash 和 publication_ids；草稿通过 drafts 临时提供，不进入正式问答索引或模型训练。scope 有效期最长 120 秒，结果保留 30 分钟并绑定租户、用户、范围和策略；翻页、详情及预览重新校验权限和来源。最多 1000 个资源、正文 10 MB，超限返回 413，不得截断后声称检测完整。共享 service_brain 的 pgvector 仍由 AI 管理。

**五类检测：**doc_exact（规范化标题相同，并非全文相同）、doc_similar（文档相似）、chunk（切片重复）、faq_ai（AI FAQ）、faq_manual（手工 FAQ）。相似度与实际比较依据由 AI 返回；跨受众合并不能扩大来源内容的可见范围。

**鉴权与异常：**沿用公共 HMAC 五个请求头。user_id 为可信数字用户主键字符串，后台停用允许约定服务身份 "0"。400 SCOPE_REQUIRED 表示缺少范围；403 GOVERNANCE_SCOPE_DENIED 表示权限失效；409 SOURCE_CHANGED / RESULT_EXPIRED 表示来源变化 / 结果过期；409 IDEMPOTENCY_CONFLICT 表示请求 ID 对应正文变化；503 AUTHORIZATION_UNAVAILABLE 表示权限数据不可用。失败不能显示“未发现重复”。
