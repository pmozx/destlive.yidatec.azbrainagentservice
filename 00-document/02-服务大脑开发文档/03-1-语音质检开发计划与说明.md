## 一、本文件说明什么

本文是**通话录音解析与质检（Agent 编排）**这一期的独立开发计划，回答四个问题：

1. 这一期交付什么——转写解析 → 四类判定 → 编排计分 → 四层报告 → 校准验收；
2. 为什么是 44.5 人日、为什么不能塞进一期 12 周——缺口 37.5 人日；
3. 复用一期的哪些能力、省了多少——复用 7 项，省 17.0 人日；
4. 怎么排、怎么验收、怎么裁——W13–W22、M8–M10、6.5 人日裁剪上限。

质检为何在一期里被记为 0 工时、14 个能力项如何拆、17.0 人日如何复用、37.5 人日缺口如何得出，见 §三；本文给出**可单独交付、可单独验收**的排期与任务口径。

### 3.3 为什么不能塞进一期 12 周

一期 59 个工作日已排 52.0 人日，仅余 7.0 人日；质检域需 44.5 人日，**缺口 37.5 人日**（约 8.7 周）。因此二期只能在一期结束后串行开始，且两期日历不重叠。

## 十二、判定与计分口径（实现约束）

| 项 | 约定 |
| --- | --- |
| 判定结果取值 | 每条规则只出三种结果：**命中 / 未命中 / 未判定**；禁止用「未命中」表达「判不了」 |
| 未判定的触发 | 证据为空、置信度低于阈值、模型输出解析失败、依赖数据缺失——四者任一即「未判定」，且必须带可读原因 |
| 单类失败降级 | 四类判定（硬规则/语义/知识一致性/工单一致性）任一失败，其余三类照常产出；失败类整体记「未判定」，不阻断整通质检 |
| 计分 | 六维分数全部由规则结果与权重计算得出，**模型不参与算分**；权重与一票否决维度可配置 |
| 报告数字 | 覆盖率、分布、Top-N、趋势一律由 SQL 聚合产生；报告解读只写文字，提示词显式禁止输出数字 |
| 复核与修正 | 修正保留原值，历史可查；复核状态流转：待复核 → 通过 / 修正 |
| 幂等 | 按 `call_id` 幂等；重复提交返回同一结果，不重复计费 |
| 可解释性 | 每条命中规则必须能定位到时间区间与原文片段；无可定位证据的命中视为缺陷 |

## 十五、计划控制

1. **周检查**：每周五核对「计划人日 vs 实际」，偏差 > 1 人日即按 §十四 裁剪；
2. **门禁**：M8 未过不进 Q5；M9 未过不进验收；M10 签字需抽检记录与人工结论；
3. **外部依赖跟踪**：§十 的 7 项外部依赖各有截止日，逾期 3 个工作日即升级书面预警；
4. **一期联动**：一期（`02-1`）延期将整段顺延本期，不用压缩质检工时补偿；
5. **春节预案**：W15 若整周休假，Q2.1/Q2.2 顺延至 W16，M8 改为 03-16，其余里程碑不变；
6. **变更**：需求方新增质检规则类型或报告维度时，先评估人日影响再承诺日期。
