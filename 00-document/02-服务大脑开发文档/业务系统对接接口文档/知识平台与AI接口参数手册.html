先看懂谁调用谁

这 13 个接口全部由 AI 团队提供，GSI 后端调用。座席页面先请求 GSI，GSI 根据登录态补齐用户、权限和签名，再请求 AI。AI 返回裸 JSON，不套 GSI 的 {code,msg,data} 外层。

1 · 解析文档POST parse/jobs → GET 查询结果 → 用户编辑确认。
2 · 发布切片GSI 审批发布 → POST knowledge/index → AI 完成入库。
3 · 搜索知识GSI 计算授权 → POST knowledge/search → 展示结果。
4 · 座席对话AI 创建会话 → GSI 授权检索 → AI 生成并保存历史。

参数怎么看：contexts[].content 表示 contexts 数组里每一条证据的正文；“父级存在时必填”表示上层对象不传时不用传，上层传了就必须提供。条件参数请同时看中文说明，特别是解析状态和被屏蔽消息。

地址：开发 Mock 为 http://127.0.0.1:18990；GSI 后端为 10200，但下列 /v1 路径不挂在 GSI 上。正式 AI 地址待团队提供。

示例 ID、签名和时间均用于说明格式，不能直接在线调用。每次请求都要生成当前时间和新 nonce，并基于实际正文重新计算签名。

公共请求头与签名

所有接口均使用 HMAC-SHA256；不传 Bearer Token，不把密钥发送给 AI。JSON 正文使用 UTF-8，Content-Type: application/json; charset=utf-8。GET 没有正文。

字段路径类型是否必需中文说明 / 约束示例值
X-AI-Signature-Versionstring必填 / 必返固定 v1。"v1"
X-AI-Client-Idstring必填 / 必返固定 gsi-service，AI 通过该标识选择共享密钥。"gsi-service"
X-AI-Timestampstring必填 / 必返13 位 Unix 毫秒，允许前后 5 分钟；示例时间不能直接用于在线调用。"1800000000000"
X-AI-Noncestring必填 / 必返每次 HTTP 请求新生成的 UUID；16–128 位字母、数字、下划线或连字符。"11111111-2222-4333-8444-555555555555"
X-AI-Signaturestring必填 / 必返原始正文签名，64 位小写十六进制 HMAC-SHA256；不是直接发送密钥。"<运行时计算的签名>"

签名原文：七行，用 LF 连接，末尾没有换行

v1
gsi-service
{X-AI-Timestamp}
{X-AI-Nonce}
{大写 HTTP 方法}
{原始路径及可选查询字符串}
{实际请求正文原始字节的 SHA-256 小写十六进制摘要}

X-AI-Signature = HMAC-SHA256(共享密钥, 上述 UTF-8 原文)，输出 64 位小写十六进制。无正文对空字节序列求 SHA-256。AI 必须在解析 JSON 前验签，不能排序字段或重序列化。

验签通过后原子登记 client_id + nonce，保留至 timestamp + 5 分钟之后。生产多实例及重启期间必须共享持久防重放记录。业务幂等 ID 重试保持不变，时间戳、nonce 和签名每次重新生成。

当前实现与交付边界

点赞 / 点踩由 GSI 管理

AI 不需要实现反馈写接口，也不需要在历史消息中返回 reaction。AI 只需保持 session_id、message_id 稳定，并按用户身份返回归属正确的消息。反馈不会递增 AI session_version，不参与 AI 生成请求幂等。

座席页面继续调用 GSI 的 POST /gsi-api/knowledge/chat/messages/{messageId}/reaction，JSON 为 {"reaction":"like"}、{"reaction":"dislike"} 或 {"reaction":null}。这是 GSI 页面接口，不计入本文件的 AI OpenAPI。

GSI 先向 AI 查询当前用户会话与消息，检查助手角色及最新知识权限，再保存到本地 sbp_km_ai_chat_feedback。仅保存 tenant_id、user_id、session_id、message_id、reaction 和时间，不复制正文。历史中的 myReaction 由 GSI 查询本地记录补齐；清空 / 删除会话成功后清理本地反馈。当前不自动将反馈同步给 AI，后续模型优化数据共享另行约定。

GSI 已适配这 13 个接口；独立 Mock 可用于真实 HTTP 联调。Mock 固定解析与生成、文件持久化、单进程执行，不代表真实大模型、历史压缩或 pgvector 已上线。AI 正式服务负责这些实现和生产可靠性。

双方共用 service_brain PostgreSQL 数据库，AI 在独立 schema（建议 ai_knowledge）维护切片、pgvector 向量、会话、消息和幂等记录，使用独立账号按 schema 授权。Embedding 模型生成向量，pgvector 保存和检索向量。GSI 通过接口访问，不直接查询 AI 表。

旧 GSI 本地会话只读，旧助手回答因缺少完整证据依赖而屏蔽；新会话由 AI 托管。知识业务状态不新增。没有 parse cancel、sync-jobs、index-jobs 或 reconcile 接口；发布后提交完整切片并等待同步最终回执。

GSI Chat 默认读取超时 60 秒，可重试错误按原正文自动重试一次，仍失败则查询原请求结果。权限变化要新建请求 ID；用户再次点击是新请求，不等于网络层幂等重试。AI 团队还需确认模型清单、容量、生成耗时、保存期限、删除策略和真实多实例并发行为。

这是离线接口文档，不含真实密钥，不提供在线执行按钮。OpenAPI 中的 JSON 示例与本页面来自同一份结构定义。

GSI 工程内如何复用这些接口

统一服务位于 gsi-backend / gsi-module-ai / com.gsi.ai.api。其他模块依赖 gsi-module-ai 并通过 Spring 注入接口，不直接依赖 AiHttpClient、不拼接 /v1 路径、不自行配置签名。

AiKnowledgeService：createKnowledgeParse、getKnowledgeParse、indexKnowledge、searchKnowledge，对应 4 个知识接口。业务模块提供已确认的内容、模型配置和授权快照；发布事件的持久化及业务状态仍归知识模块。

AiConversationService：createSession、querySessions、getSession、renameSession、deleteSession、queryMessages、clearMessages、complete、queryRequest，对应 9 个 Chat 接口。另提供 listSessions / listMessages 自动遍历分页，以及 tenantId 供本地反馈关联。Access 包含可信 userId 与实时授权提供器，Evidence 包含引用别名、检索命中和完整切片。

AI 模块内部统一构造请求 ID、授权时间窗、提示词 / 模型参数，处理签名、超时、原请求重试、分页与请求结果恢复。Chat 返回经过协议校验的 JsonNode；调用模块继续逐项复核知识权限、校验引用原文并映射页面字段。不得把首次授权永久缓存，也不得将浏览器自报身份放入 Access。

知识和座席模块不再直接注入 HTTP 客户端或 AI 地址 / 密钥配置。旧 AiTeamClient 等历史接口不属于本次 13 个接口的公共入口，新模块使用 com.gsi.ai.api 下的两个服务。点赞点踩继续由 GSI 业务模块管理。
