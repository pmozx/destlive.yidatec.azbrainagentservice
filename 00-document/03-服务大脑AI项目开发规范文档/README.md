## 四、维护约定

1. **规范的变更要留痕**：修改规则时在同一次提交内更新文首「变更记录」与受影响条目的正反示例；不删除已生效的规则编号（作废时标注「已废止（日期）+ 原因」）。
2. **规则编号稳定**：`R`（Python）/ `F`（FastAPI）/ `D`（Database）/ `L`（LangChain）/ `T`（Test）编号一经使用不复用，便于报告与 PR 引用。
3. **正反示例必须来自真实代码或真实反模式**：反例优先引用存量代码位置（文件:行号），正例优先指向已落地的写法，避免「理论正确但项目里不存在」的示例。
4. **新增规范先判定归属**：能归入现有章节的扩写该章节；确需新章（如新增中间件、消息队列），先在本 README 的文件清单里登记覆盖范围再落笔。
5. **工具优先于口头规范**：凡是能由 `ruff` / `mypy` / CI 卡住的约束，写进 `pyproject.toml` 或 `.pre-commit-config.yaml`，规范正文只保留「为什么」。
