## 二、接口契约与字段约束

### 2.1 接口摘要

| 接口 | 方法 | 路径 | 用途 | 成功响应 | 失败场景 |
| --- | --- | --- | --- | --- | --- |
| #01 | POST | `/v1/parse/jobs` | 提交文档 / FAQ 解析任务 | 202 Accepted（受理回执） | 400 INVALID_REQUEST / 413 PAYLOAD_TOO_LARGE |
| #02 | GET | `/v1/parse/jobs/{job_id}` | 查询解析进度与完整结果 | 200 OK（任务快照） | 404 NOT_FOUND |

**公共约束**：

- 所有请求携带 HMAC-SHA256 签名头（5 个公共头，见 §2.4）；GET 无正文时按空字节序列计算摘要
- `#01` 返回 202 只表示**已受理**，不代表解析成功；结果必须轮询 `#02`
- 解析失败属于**任务结果**：`#02` 仍返回 HTTP 200 + `error_code=PARSE_FAILED`
- `status` 四态：`queued` → `running` → `succeeded` / `failed`；`progress` 为 0–100 整数，终态必为 100

### 2.2 #01 请求字段与校验规则

| 字段 | 类型 | 必填 | 校验规则 / 说明 |
| --- | --- | --- | --- |
| job_id | string | 必填 | 非空；同时是幂等键，重试必须复用同一值 |
| doc_id | string | 必填 | 非空；文档 / 本次解析所属业务资源 ID |
| version_id | string | 必填 | 非空；业务版本标识，不按数字比较 |
| file_url | string | 必填 | http/https，服务端可直接拉取 |
| file_name | string | 必填 | 带扩展名；扩展名决定解析器（.pdf / .docx / .md） |
| options.chunk | boolean | 必填 | 当前固定 `true` |
| options.language | string | 必填 | 非空，与 `metadata.language` 保持一致 |
| tenant_id | string | 必填 | 当前固定 `gsi-default` |
| resource_type | string | 必填 | 枚举 `document` / `faq` |
| metadata | object | 必填 | 页面已保存的元数据快照（`extra=ignore`） |
| file_id | string | 可选 | 仅追踪用 |
| file_size | integer | 可选 | ≥ 0；超过 10MB（10485760 字节）返回 413 |
| prompt_text | string | 条件必填 | `resource_type=faq` 时必填，且不能仅含空白字符 |
| model_key | string | 条件必填 | `resource_type=faq` 时必填，且不能仅含空白字符 |

### 2.3 #02 响应字段

**公共字段（任意状态）**：`job_id`（string）、`status`（queued / running / succeeded / failed）、`progress`（0–100）。

**成功态 `result`**：

| 字段 | 类型 | 必返 | 说明 |
| --- | --- | --- | --- |
| result.file_name | string | 可选 | 原始文件名 |
| result.suggested_doc_type | string | 可选 | AI 建议的文档分类（FAQ 场景为 `FAQ`） |
| result.suggested.title / summary / tags | string / string / array | 可选 | 复用 `#01` 传入的 metadata 已填值 |
| result.pages[] | array | 必返 | PDF 页图；非 PDF 返回 `[]`；元素含 `page_no` / `width` / `height` / `image_url` |
| result.chunks[] | array | 必返 | 切片；含 `seq` / `content` / `source_type`，可选 `heading` / `page_from` / `page_to` |
| result.warnings[] | array<string> | 必返 | 无警告返回 `[]` |

**失败态**：`error_code`（机器可读，如 `PARSE_FAILED`）+ `error_message`（人类可读）。

**错误响应结构**（`#01` 的 4xx 与 `#02` 的 404）：`error.code` / `error.message` / `error.retryable`。

### 2.4 公共请求头（5 个签名头）

| 头名 | 说明 |
| --- | --- |
| X-AI-Signature-Version | 固定 `v1` |
| X-AI-Client-Id | 客户端标识，测试环境为 `gsi-service` |
| X-AI-Timestamp | 13 位 Unix 毫秒时间戳 |
| X-AI-Nonce | 16–128 位随机字符串 |
| X-AI-Signature | HMAC-SHA256 签名 |

签名原文 7 行：`v1` / `client_id` / `timestamp` / `nonce` / 大写方法 / `path+query` / body SHA-256。测试中不手拼，统一由 `/v1/test/signed-headers` 生成（见 §7.3）。

| 55 | 分片 / FAQ 提取完成 |
| 80 | 页图渲染完成 |
| 95 | 建议元数据生成完成 |
| 100 | 任务完成（succeeded / failed） |

**状态流转**：`queued (0)` → `running (35)` → `running (55)` → `running (80)` → `running (95)` → `succeeded (100)` / `failed`

**断言要点**：

- `progress` 单调不减（不回退）
- `status` 只按四态顺序流转，不出现回跳
- 非终态不含 `result`；终态必须有 `result` 或 `error_code`
- 任务失败时 HTTP 仍为 200，仅 `status=failed` + `error_code`

**失败态样例**：

```json
{
  "job_id": "parse-doc-100001",
  "status": "failed",
  "progress": 35,
  "error_code": "PARSE_FAILED",
  "error_message": "无法识别文档内容。"
}
```

### 7.3 签名头生成与手工 curl

| 方式 | 用法 | 适用 |
| --- | --- | --- |
| 测试辅助接口 | `POST` / `GET` `/v1/test/signed-headers?method=...&path=...`，body 传原始正文 | curl / Apifox 联调 |

```bash
# 1. 取签名头：method / path 走 query，body 用 --data-binary 传同一份文件
curl -X POST "http://127.0.0.1:8002/v1/test/signed-headers?method=POST&path=/v1/parse/jobs" ^
  --data-binary "@..\00-document\06-服务大脑AI项目测试用例与结果文档\test-data\requests\01_parse_jobs_doc.json"

  -H "Content-Type: application/json" ^
  -H "X-AI-Signature-Version: v1" -H "X-AI-Client-Id: gsi-service" ^
  -H "X-AI-Timestamp: <timestamp>" -H "X-AI-Nonce: <nonce>" -H "X-AI-Signature: <signature>" ^
  --data-binary "@..\00-document\06-服务大脑AI项目测试用例与结果文档\test-data\requests\01_parse_jobs_doc.json"
```

> `-d` / `--data-raw` 会改写换行导致摘要失配，必须用 `--data-binary @文件`。
