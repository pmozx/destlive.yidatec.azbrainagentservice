# 02 · 查询解析进度接口（#02）测试用例

> 测试目标：验证 `/v1/parse/jobs/{job_id}`（#02 查询解析进度与结果）的完整出入参契约
> 测试日期：2026-11-03
> 前置条件：已通过 #01 接口提交解析任务，获得有效的 `job_id`

---

## 一、接口契约摘要

| 项目 | 说明 |
|------|------|
| 接口 | #02 查询解析进度与完整结果 |
| 方法 | GET |
| 路径 | `/v1/parse/jobs/{job_id}` |
| 请求正文 | 无（GET 请求，签名使用空字节序列的 SHA-256） |
| 成功响应 | HTTP 200 OK |
| 失败场景 | HTTP 404 Not Found（任务不存在） |

**关键约束**：
- 解析失败属于**任务结果**，HTTP 仍返回 200 + `error_code=PARSE_FAILED`
- `status` 四态流转：`queued` → `running` → `succeeded` / `failed`
- `progress` 为 0–100 的整数，终态时必须为 100

---

## 二、请求参数

### 2.1 路径参数

| 参数 | 类型 | 必填 | 说明 | 示例值 |
|------|------|------|------|--------|
| job_id | string | 必填 | #01 提交任务时传入的 `job_id` | "parse-doc-100001" |

### 2.2 请求头

所有请求需携带 HMAC-SHA256 签名头（5 个公共头）：

| 头名 | 说明 |
|------|------|
| X-AI-Signature-Version | 固定 "v1" |
| X-AI-Client-Id | 客户端标识，如 "gsi-service" |
| X-AI-Timestamp | 13 位 Unix 毫秒时间戳 |
| X-AI-Nonce | 16–128 位随机字符串 |
| X-AI-Signature | HMAC-SHA256 签名 |

**使用测试辅助接口生成签名头**：

```bash
# 先调用 /v1/test/signed-headers 生成签名头
curl -X POST http://127.0.0.1:8002/v1/test/signed-headers ^
  -H "Content-Type: application/json" ^
  -d "{\"method\": \"GET\", \"path\": \"/v1/parse/jobs/parse-doc-100001\"}"
```

---

## 三、响应字段说明

### 3.1 公共字段（所有状态均返回）

| 字段 | 类型 | 必返 | 说明 |
|------|------|------|------|
| job_id | string | 必返 | 任务 ID |
| status | string | 必返 | 任务状态：queued / running / succeeded / failed |
| progress | integer | 必返 | 进度百分比 0–100 |

### 3.2 成功态字段（status=succeeded）

| 字段 | 类型 | 必返 | 说明 |
|------|------|------|------|
| result | object | 必返 | 解析结果对象 |
| result.file_name | string | 可选 | 原始文件名 |
| result.suggested_doc_type | string | 可选 | AI 建议的文档分类 |
| result.suggested | object | 可选 | AI 建议元数据 |
| result.suggested.title | string | 可选 | 建议标题 |
| result.suggested.summary | string | 可选 | 建议摘要 |
| result.suggested.tags | array<string> | 可选 | 建议标签 |
| result.pages | array | 必返 | PDF 页图列表，无页图时返回 [] |
| result.pages[].page_no | integer | 必返 | 页码，从 1 开始 |
| result.pages[].width | integer | 必返 | 预览图宽度（像素） |
| result.pages[].height | integer | 必返 | 预览图高度（像素） |
| result.pages[].image_url | string | 必返 | 页图 URL |
| result.chunks | array | 必返 | 切片列表 |
| result.chunks[].seq | integer | 必返 | 切片序号，从 1 开始 |
| result.chunks[].heading | string | 可选 | 切片小标题 |
| result.chunks[].content | string | 必返 | 切片正文内容 |
| result.chunks[].page_from | integer | 可选 | 起始页码 |
| result.chunks[].page_to | integer | 可选 | 结束页码 |
| result.chunks[].source_type | string | 可选 | 内容来源类型，如 "text" |
| result.warnings | array<string> | 必返 | 警告列表，无警告返回 [] |

### 3.3 失败态字段（status=failed）

| 字段 | 类型 | 必返 | 说明 |
|------|------|------|------|
| error_code | string | 必返 | 机器可读错误码，如 "PARSE_FAILED" |
| error_message | string | 必返 | 人类可读错误说明 |

## 四、测试用例

### 用例 #1：查询排队中的任务

**前置条件**：刚通过 #01 提交任务，后台尚未开始执行

**请求**：
```
GET /v1/parse/jobs/parse-doc-100001
```

**期望响应**（HTTP 200）：
```json
{
  "job_id": "parse-doc-100001",
  "status": "queued",
  "progress": 0
}
```

**断言要点**：
- `status` 为 "queued"
- `progress` 为 0
- 无 `result` 字段（任务未完成）

---

### 用例 #2：查询执行中的任务

**前置条件**：任务已开始执行，但尚未完成

**请求**：
```
GET /v1/parse/jobs/parse-doc-100001
```

**期望响应**（HTTP 200）：
```json
{
  "job_id": "parse-doc-100001",
  "status": "running",
  "progress": 35
}
```

**断言要点**：
- `status` 为 "running"
- `progress` 为 0–99 之间的整数
- 无 `result` 字段（任务未完成）

**进度节点参考**：
| progress | 阶段 |
|----------|------|
| 0 | 任务已入队 |
| 35 | 文档解析完成 |
| 55 | 分片/FAQ 提取完成 |
| 80 | 页图渲染完成 |
| 95 | 建议元数据生成完成 |
| 100 | 任务完成 |

---

### 用例 #5：查询失败的任务

**前置条件**：任务执行失败（如文档无法解析）

**请求**：
```
GET /v1/parse/jobs/parse-doc-100001
```

**期望响应**（HTTP 200）：
```json
{
  "job_id": "parse-doc-100001",
  "status": "failed",
  "progress": 35,
  "error_code": "PARSE_FAILED",
  "error_message": "无法识别文档内容。"
}
```

**断言要点**：
- **HTTP 仍为 200**（任务失败 ≠ 请求失败）
- `status` 为 "failed"
- `error_code` 存在且为机器可读错误码
- `error_message` 存在且为人类可读说明

---

### 用例 #6：查询不存在的任务

**请求**：
```
GET /v1/parse/jobs/non-existent-job-id
```

**期望响应**（HTTP 404）：
```json
{
  "request_id": "（请求 ID）",
  "error": {
    "code": "NOT_FOUND",
    "message": "解析任务 non-existent-job-id 不存在。",
    "retryable": false
  }
}
```

**断言要点**：
- HTTP 状态码为 404
- `error.code` 为 "NOT_FOUND"
- `error.message` 包含任务 ID

---

### 用例 #7：轮询任务至终态（完整流程）

**测试步骤**：
1. 通过 #01 提交新的解析任务，获取 `job_id`
2. 立即调用 #02，期望 `status=queued`
3. 每隔 2 秒轮询 #02，观察 `status` 和 `progress` 变化
4. 等待 `status` 变为 `succeeded` 或 `failed`

**期望状态流转**：
```
queued (progress=0)
  ↓
running (progress=35)
  ↓
running (progress=55)
  ↓
running (progress=80)
  ↓
running (progress=95)
  ↓
succeeded (progress=100) 或 failed
```

**断言要点**：
- `progress` 单调递增（不会回退）
- `status` 按四态顺序流转
- 终态时 `result` 或 `error_code` 必存在

## 五、测试执行命令

### 5.1 使用 curl 测试

```bash
# 1. 先生成签名头
curl -X POST http://127.0.0.1:8002/v1/test/signed-headers ^
  -H "Content-Type: application/json" ^
  -d "{\"method\": \"GET\", \"path\": \"/v1/parse/jobs/parse-doc-100001\"}"

# 2. 使用返回的签名头调用 #02 接口
curl -X GET http://127.0.0.1:8002/v1/parse/jobs/parse-doc-100001 ^
  -H "X-AI-Signature-Version: v1" ^
  -H "X-AI-Client-Id: gsi-service" ^
  -H "X-AI-Timestamp: <timestamp>" ^
  -H "X-AI-Nonce: <nonce>" ^
  -H "X-AI-Signature: <signature>"
```

### 5.2 使用 Python 测试

```python
import httpx
import json

BASE_URL = "http://127.0.0.1:8002"

def get_signed_headers(method: str, path: str, body: str = "") -> dict:
    """调用测试辅助接口生成签名头"""
    resp = httpx.post(f"{BASE_URL}/v1/test/signed-headers", json={
        "method": method,
        "path": path,
        "body": body,
    })
    return resp.json()["headers"]

def query_parse_job(job_id: str) -> dict:
    """查询解析任务状态"""
    headers = get_signed_headers("GET", f"/v1/parse/jobs/{job_id}")
    resp = httpx.get(f"{BASE_URL}/v1/parse/jobs/{job_id}", headers=headers)
    return resp.json()

# 测试用例
result = query_parse_job("parse-doc-100001")
print(json.dumps(result, indent=2, ensure_ascii=False))
```
