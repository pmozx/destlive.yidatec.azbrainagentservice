# 01 · 提交解析任务接口（#01）测试用例

> 测试目标：验证 `/v1/parse/jobs`（#01 提交解析任务）的完整出入参契约
> 测试日期：2026-11-03
> 测试环境：本地开发环境（PostgreSQL + MinIO + LLM 服务）
> 用例来源：`backend/tests/contract/debug_json/01_parse_jobs_doc.json` 与 `01_parse_jobs_fqa.json`

---

## 一、接口契约摘要

| 接口 | 方法 | 路径 | 用途 | 成功 HTTP |
| --- | --- | --- | --- | --- |
| #01 | POST | `/v1/parse/jobs` | 提交文档 / FAQ 解析任务 | 202 Accepted |

**公共约束**：
- 所有请求需携带 HMAC-SHA256 签名头（5 个公共头，见接口手册 §五）
- `#01` 返回 202 表示任务已受理，**不表示解析成功**；解析结果需轮询 `#02`
- 解析失败属于**任务结果**：`#02` 仍返回 HTTP 200 + `error_code=PARSE_FAILED`

## 二、用例 #1：文档解析（resource_type=document）

### 2.1 入参（请求正文）

```json
{
  "job_id": "parse-doc-100001",
  "doc_id": "doc-demo-10001",
  "version_id": "v1",
  "file_url": "https://cdn-mineru.openxlab.org.cn/demo/example.pdf",
  "file_name": "Lane_2005_造林与流量历时曲线.pdf",
  "options": {
    "chunk": true,
    "language": "zh"
  },
  "tenant_id": "gsi-default",
  "resource_type": "document",
  "file_size": 1024,
  "metadata": {
    "title": "造林对流量历时曲线的影响"
  }
}
```

### 2.2 期望出参（202 Accepted）

```json
{
  "job_id": "parse-doc-100001",
  "status": "queued",
  "message": "任务已受理，请查询结果。"
}
```

**断言要点**：
- `status` 必须为 `queued`（任务已入队，等待后台执行）
- `message` 为固定提示文案
- `job_id` 与请求入参一致

## 四、异常场景用例

### 4.1 文件类型不支持

**入参变更**：`file_name: "readme.txt"`（假设 .txt 不在支持列表）

**期望出参（400 Bad Request）**：

```json
{
  "request_id": "（从请求头或正文补回）",
  "error": {
    "code": "invalid_request",
    "message": "暂不支持解析 .txt 文件；已接入：.pdf/.docx/.md。"
  }
}
```

### 4.2 文件超过 10MB 上限

**入参变更**：`file_size: 11000000`（超过 10MB）

**期望出参（413 Payload Too Large）**：

```json
{
  "request_id": "（从请求头或正文补回）",
  "error": {
    "code": "payload_too_large",
    "message": "文件超过 10MB 上限。"
  }
}
```

### 4.3 FAQ 缺失 prompt_text

**入参变更**：`resource_type: "faq"`，但 `prompt_text` 省略或为空

**期望出参（400 Bad Request）**：

```json
{
  "request_id": "（从请求头或正文补回）",
  "error": {
    "code": "invalid_request",
    "message": "resource_type 为 faq 时，prompt_text 必填且不能仅包含空白字符。"
  }
}
```

### 4.4 幂等重试（同 job_id 同正文）

**入参**：使用用例 #1 或 #2 的完整入参，重复发送一次

**期望出参（202 Accepted）**：

```json
{
  "job_id": "parse-doc-100001",
  "status": "queued",
  "message": "任务已受理，请查询结果。"
}
```

**断言要点**：
- 返回与首次请求**完全相同**的受理回执
- 不重复创建任务行（数据库 `job_id` 唯一约束）

## 六、测试执行与结果记录

### 6.1 使用测试辅助接口生成签名头

为简化测试流程，项目提供了 `/v1/test/signed-headers` 接口，可自动生成合法的 HMAC 签名头。

**前提条件**：`env/.env.dev` 中配置 `CONTRACT_TEST_ENABLE=true`

**请求示例**：

```bash
# 为 POST /v1/parse/jobs 生成签名头
curl -X POST http://127.0.0.1:8002/v1/test/signed-headers ^
  -H "Content-Type: application/json" ^
  -d "{\"method\": \"POST\", \"path\": \"/v1/parse/jobs\", \"body\": \"{\\\"job_id\\\":\\\"parse-doc-100001\\\",...}\"}"
```

**响应示例**：

```json
{
  "headers": {
    "X-AI-Signature-Version": "v1",
    "X-AI-Client-Id": "gsi-service",
    "X-AI-Timestamp": "1730620800000",
    "X-AI-Nonce": "abc123def456...",
    "X-AI-Signature": "a1b2c3d4e5f6..."
  },
  "signing_string": "v1\ngsi-service\n1730620800000\nabc123def456...\nPOST\n/v1/parse/jobs\n...",
  "client_id": "gsi-service",
  "timestamp_ms": 1730620800000,
  "nonce": "abc123def456..."
}
```

**使用方式**：将响应中的 `headers` 对象的所有键值对作为请求头发送即可。

## 八、附录：签名头生成示例

```python
import hashlib
import hmac
import time
import uuid

CLIENT_ID = "gsi-service"
SHARED_SECRET = "<从配置获取>"
METHOD = "POST"
PATH = "/v1/parse/jobs"
BODY = b'{"job_id":"parse-doc-100001",...}'

timestamp = str(int(time.time() * 1000))
nonce = str(uuid.uuid4())

# 签名原文拼装
signing_string = f"{METHOD}\n{PATH}\n{timestamp}\n{nonce}\n{hashlib.sha256(BODY).hexdigest()}"

# HMAC-SHA256 签名
signature = hmac.new(
    SHARED_SECRET.encode(),
    signing_string.encode(),
    hashlib.sha256
).hexdigest()

# 请求头
headers = {
    "Content-Type": "application/json",
    "X-AI-Signature-Version": "v1",
    "X-AI-Client-Id": CLIENT_ID,
    "X-AI-Timestamp": timestamp,
    "X-AI-Nonce": nonce,
    "X-AI-Signature": signature,
}
```
