### 1.2 前置数据（两个会话各司其职）

会话与消息是**写库状态**，破坏性用例（#12 删除、#13 清空）一旦作用在主会话上，整套用例就无法重复执行。因此脚本创建**两个会话**：

| 会话 | 创建请求 | 固定 `request_id` | 用于 |
|------|----------|-------------------|------|
| 主会话 A | `06_chat_session_create.json` | `req-chat-session-create-001` | #09 列表、#10 详情（含历史）、#11 改名、#14 问答、#15 查结果 |
| 临时会话 B | `06_chat_session_create_temp.json` | `req-chat-session-temp-001` | #13 清空、#12 删除、删除后的 #10（预期 404） |

`session_id` 由 AI 分配，无法预写，脚本按 `__SESSION_ID__` / `__TEMP_SESSION_ID__` 占位符在发送前注入。

> **可重复执行**：#08 用固定 `request_id` + 固定正文，重跑时幂等台账回放同一个 `session_id`，后续用例始终有会话可查；若改了标题等正文字段却不换 `request_id`，会命中 `409 IDEMPOTENCY_CONFLICT`。

## 二、接口契约与字段约束

### 2.1 请求正文

公共字段（#08–#15 全部必填）：

| 字段 | 类型 | 约束 |
|------|------|------|
| `request_id` | string | 本次操作 ID；写操作同时是幂等键 |
| `tenant_id` | string | 当前固定 `gsi-default`；只做回显与审计，不参与归属判断 |
| `user_id` | string | GSI 登录用户的**数字主键**字符串；非数字 400 `INVALID_REQUEST` |

各接口差异：

| 接口 | 路径 | 专有字段 | `authorization` |
|------|------|----------|-----------------|
| #08 建会话 | POST `/v1/chat/sessions` | `title`（可选，≤100 字符，缺省「新对话」） | **可选** |
| #09 列表 | POST `/v1/chat/sessions/query` | `cursor`、`limit`（1–100，默认 20） | **必填** |
| #10 详情 | POST `/v1/chat/sessions/{session_id}/query` | `include_messages`（默认 false）、`cursor`、`limit` | **必填** |
| #11 改名 | PATCH `/v1/chat/sessions/{session_id}` | `title`（必填，1–100） | **可选** |
| #12 删除 | DELETE `/v1/chat/sessions/{session_id}` | 无（正文只承载身份与幂等键） | **可选** |
| #13 清空 | DELETE `/v1/chat/sessions/{session_id}/messages` | 无 | **可选** |
| #14 问答 | POST `/v1/chat/completions` | `session_id`、`question`、`prompt_text`、`model_key`、`stream`、`options.language`、`options.max_output_tokens`（1–8192） | **必填** |
| #15 查结果 | POST `/v1/chat/requests/{target_request_id}/query` | 无（正文 `request_id` 是本次查询的新 ID） | **必填** |

`authorization` 块：`scope_id` 非空、`issued_at` / `expires_at` 为 Unix 毫秒、`expires_at > issued_at` 且跨度 ≤120 秒，已过期 401、跨度超限 400。

> **为什么 #08 / #11 / #12 / #13 的授权块是可选**：手册对这四条写的是「可选」，对 #09 / #10 / #14 / #15 写「必填」。把可选放宽成必填（或反之）会掩盖契约差异，所以按接口分别声明，时效校验统一交给路由依赖。

### 2.2 响应正文

| 接口 | 关键字段 |
|------|----------|
| #08 / #11 | `request_id`、`session_id`、`title`、`created_at`、`updated_at` |
| #09 | `request_id`、`sessions[]{session_id,title,created_at,updated_at}`、`next_cursor` |
| #10 | 会话四字段 + `messages[]`、`next_cursor`（`include_messages=false` 时**整体省略**） |
| #12 | `request_id`、`session_id`、`deleted=true` |
| #13 | `request_id`、`session_id`、`cleared=true` |
| #14 | `request_id`、`session_id`、`user_message_id`、`assistant_message_id`、`status=completed`、`answer`、`citations[]`、`source_snapshots[]`、`authorization_scope_id`、`no_evidence`、`finish_reason` |
| #15 | `request_id`、`operation`（completion / mutation / delete）、`status`（pending / completed / failed / cancelled）、`result_visible`、`result`、`reason`、`error{code,message,retryable}` |

三条投影口径：

1. **时间统一 `YYYY-MM-DDTHH:MM:SSZ`**：UTC 秒级带 `Z`，不用毫秒、不输出 `+08:00`；
2. **条件必返字段整体省略**：`messages` / `content` / `citations` / `reason` 在本场景不适用时由 `response_model_exclude_none` 省略，而不是回 `null` 或空串；
3. **助手消息必须带齐 `citations[]` 与 `source_snapshots[]`**：GSI 会逐项再授权，缺一项就得整条隐藏（`content_visible=false` + `reason`）。

### 2.3 拒绝顺序（谁先拦）

| 顺序 | 校验点 | 失败表现 |
|------|--------|----------|
| 1 | 签名鉴权（公共 5 头） | 401 `UNAUTHORIZED` |
| 2 | 正文 Schema（身份非空 / `user_id` 数字 / 授权块必填与否 / 枚举与范围） | 400 `INVALID_REQUEST` |
| 3 | `authorization` 时效（跨度 ≤120s、未过期） | 400 / 401 |
| 4 | 业务：会话归属、幂等回放、台账可见性 | 200 / 404 / 409 / 503 / 500 |

> 会话归属失败的三种情况——**不存在 / 不属于本人 / 已删除**——对调用方是同一件事，一律 404，不泄漏存在性。
> 生成期间会话被删除或清空，不是技术故障：#14 回 409 `RESULT_EXPIRED`，台账按「已作废」登记（#15 映射为 `cancelled`）。

## 五、实现依据与已知风险

| 结论 | 依据 |
|------|------|
| 幂等域按接口分工 | #08/#11/#14 走请求域 `idempotent_request`；#12/#13 走事件域 `idempotent_event` 并留墓碑（`expires_at=NULL`），防止「删除后重发同一 ID」把已删内容复活；#09/#10/#15 不占幂等键 |
| #15 不直接回台账 | 台账只存回执（不含正文），`answer` 按 `assistant_message_id` 回查消息表，顺带复核「这条答案现在还应不应该给」 |
| #14 先拒 `stream=true` | 在进入检索与模型调用**之前**拒绝，省一次昂贵调用，也让调用方立刻知道该改参数 |
| 历史消息可见性逐条重判 | 依赖知识可能已撤权、发布单元可能换版、会话可能已清空；不可见时只回 `message_id` / `role` / `created_at` / `reason` |

**已知风险（执行时需留意）**：

1. #14 依赖模型与向量化两个外部依赖，二者任一不可用都会让用例 6/7/8 连锁失败——此时应先查依赖，而不是判契约缺陷；
2. #15 在「#14 成功但随后清空/删除会话」时返回 `result_visible=false` + `reason=SOURCE_UNAVAILABLE`，这是正确行为，不应判为失败；
3. 重复执行脚本时，#14 命中幂等回放，不会新增消息；主会话历史里始终保持首轮的一问一答。

## 六、结论

1. **契约口径已固化**：8 个接口的请求字段、授权块必填与否、响应条件必返字段、拒绝顺序与错误码映射均已逐条对照手册落进用例数据与脚本断言。
