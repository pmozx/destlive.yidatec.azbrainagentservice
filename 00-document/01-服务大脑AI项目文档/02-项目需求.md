## 三、系统边界与职责划分

### 3.1 定位

本项目交付的是**被 GSI 调用的 AI 服务**。工程形态为前后端一体仓库：后端为交付主体，前端仅保留基座既有管理页面（日志审计、监控等），不新增业务页面。

### 3.2 职责划分（强制口径）

| 能力 | GSI | AI 服务 | 说明 |
| --- | --- | --- | --- |
| 工单/录音/ASR/CTI 数据 | 生产与持有 | 只消费 | AI 不创建、不修改业务事实；转写文本由 GSI 提供 |
| 权限计算（部门/项目/指定人） | 提供数据源 | 按签名身份实时计算 | AI **只读查询 7 张指定共享表**，规则变更由双方同步（见 §十二-3） |
| 知识业务状态（草稿/审批/发布） | 维护 | 只接收"批准后的正式切片集合" | 停用/删除以 #06 / #20 下发 |
| 知识分片与向量 | 不参与 | 生成与维护 | 切片 `chunk_id` 与 GSI 的 publication/record 建立六元组映射 |
| 质检规则内容的业务口径 | 业务确认 | 只做配置校验与执行 | 规则文本由业务 Owner 维护 |
| 判定结论 | 展示与复核 | 产出判定与证据 | 最终绩效结论以复核为准 |
| 会话与历史消息 | 展示 | 托管与查询 | 归属校验按签名身份（user_id） |
| 反馈（点赞点踩） | 采集并保存 | 不参与 | AI 保证 `session_id`/`message_id` 稳定 |
| 调用签名 | 生成与保管 | 校验与审计 | 共享密钥双方约定，密钥不入库不入仓 |

### 3.3 系统上下文

```
        ┌──────────────┐   ① /v1 契约调用（HMAC 四头签名 · 20 接口）
        │   GSI 业务系统 │ ─────────────────────────────────┐
        │  工单/录音/知识 │                                 ▼
        │  权限/报表/前台 │ ◄──── ② 判定与问答结果（裸 JSON） ┌────────────────────┐
        └──────────────┘                                  │   AI 服务            │
                                                          │  ┌────────────────┐ │
        ┌──────────────┐   ③ 只读查询 7 张共享表（共库）      │  │ LangGraph 编排  │ │
        │ service_brain │ ◄────────────────────────────── │  └────────────────┘ │
        │ PostgreSQL    │                                 │  ┌────────────────┐ │
        │  GSI 93 表    │ ───► sbp_ai_* 表（同库 public）──► │  │ sbp_ai_* 表    │ │
        └──────────────┘                                 │  └────────────────┘ │
                                                         └────────────────────┘
        ┌──────────────┐   ④ 嵌入/重排（内网 HTTP）                  │
        │ 私有化模型服务 │ ◄──────────────────────────────────────────┤
        │ bge-m3/rerank│                                            │
        └──────────────┘   ⑤ 对话补全（HTTPS，OpenAI 兼容端点）        │
        ┌──────────────┐ ◄──────────────────────────────────────────┘
        │ ChatGPT 5.6  │
        └──────────────┘
```

**数据存储总口径**（v2.1 契约 + 本项目决策）：双方共用 `service_brain` PostgreSQL 数据库；AI 使用独立数据库账号；AI 自有表全部落 **public schema** 并以 **`sbp_ai_` 前缀**隔离；GSI 的 7 张共享表按指定字段只读开放；pgvector 用于向量存储与检索。

## 四、角色与用例

| 用例 | 角色 | 触发 | 主流程 | 结果 |
| --- | --- | --- | --- | --- |
| UC-01 知识入库 | 知识 Owner（经 GSI） | 文档/FAQ 变更 | 提交解析（#01）→ 轮询进度（#02）→ GSI 校对修订 → 审批通过后写入（#03/#05） | 知识可检索，旧版本被替换 |
| UC-02 知识下架 | 知识 Owner（经 GSI） | 知识过期/删除 | 审批后调用 #06 删除或 #20 停用 | 该发布单元不可召回，保留幂等墓碑 |
| UC-03 坐席问答 | 坐席（经 GSI） | 客户提问 | 创建会话（#08）→ 提问（#14）→ 得到带引用答案 | 答案 + 引用六元组 + 会话留痕 |
| UC-04 无依据拒答 | 坐席（经 GSI） | 问题超出知识范围 | 召回无命中或低于阈值 | 明确返回"无依据"，不生成推测 |
| UC-05 重复治理 | 知识 Owner（经 GSI） | 录入前/治理期 | 查重（#16）→ 分组（#17）→ 详情对比（#18）→ 合并预览（#19）→ 停用（#20） | 重复知识可发现、可合并、可停用 |
| UC-06 单通质检 | 质检流程（经 GSI） | 通话结束 | 转写 → 四类判定 → 计分 → 产出单通结果 | 分数 + 缺陷 + 证据片段 |
| UC-07 一致性校验 | 质检流程（经 GSI） | 坐席回答涉知识 | 召回相关条目 → 比对 → 标注差异 | 一致/不一致 + 差异说明 |
| UC-08 报告生成 | 项目经理 | 周期结束 | 聚合统计 → 生成解读文字 | 员工/团队报告 |
| UC-09 复盘申诉 | 质检员/坐席 | 对结论有异议 | 提交复核 → 修正判定 → 回流样本 | 判定可修正，样本可回灌 |
| UC-10 效果监控 | 模型运营 | 每周 | 查看判定分布、拒答率、引用命中率 | 调优依据 |
| UC-11 联调自检 | GSI 开发 | 上线前 | 20 接口逐个打通正常/异常用例 | 联调记录 |
| UC-12 安全审计 | 安全/合规 | 事后追溯 | 按时间/调用方/路径检索审计日志，查看安全头校验结果 | 调用链可还原，异常调用可定位 |

## 五、功能需求

### 5.1 集成与接入（FR-INT）

| 编号 | 需求 | 优先级 | 验收标准 |
| --- | --- | --- | --- |
| FR-INT-01 | 必须实现 v2.1 契约的 20 个 `/v1/*` 接口（#01–#20 顺序编号），路径、方法、字段与手册完全一致 | P0 | 契约比对脚本 0 差异 |
| FR-INT-02 | 全部对外接口必须使用 HMAC-SHA256 四头签名鉴权（`X-AI-Client` / `X-AI-Timestamp` / `X-AI-Nonce` / `X-AI-Signature`），不挂 JWT Bearer | P0 | 缺头/错签/过期/重放四类用例均被拒，错误码符合契约 |
| FR-INT-03 | 签名原文必须使用原始请求路径（含查询串）与原始请求体字节摘要，禁止中间件重排 JSON 或改写路径 | P0 | 含中文、含转义、含空 body 三类用例签名通过 |
| FR-INT-04 | 必须实现 nonce 持久化防重放（表 `sbp_ai_system_nonce`），时间窗 ±5 分钟，多实例共享 | P0 | 同 nonce 二次请求被拒；服务重启后仍拒绝 |
| FR-INT-05 | 必须实现幂等台账（表 `sbp_ai_system_idempotency`）：`job_id` / `request_id` 等写操作幂等键，同 ID 同正文返回首次结果，同 ID 异正文 409 | P0 | 重试同正文返回首次结果；异正文 409 |
| FR-INT-06 | 错误响应必须为契约定义的统一错误体（含 `code` / `message` / `retryable` / `request_id`），覆盖契约错误码 | P0 | 错误码逐一可复现（含 v2 新增 `SCOPE_REQUIRED`/`GOVERNANCE_SCOPE_DENIED`/`SOURCE_CHANGED`/`RESULT_EXPIRED`/`AUTHORIZATION_UNAVAILABLE`） |
| FR-INT-07 | 授权对象 `authorization{scope_id, issued_at, expires_at}` 必须校验时效（≤120 秒）；AI 必须按签名身份查询 7 张共享表计算实时权限，权限数据不可用时返回 503 `AUTHORIZATION_UNAVAILABLE`，禁止退化为全库检索 | P0 | 过期授权被拒；停共享表账号后接口 503 而非越权返回 |
| FR-INT-08 | 检索与生成必须在计算出的授权范围内执行（权限条件下推 SQL），禁止先全库召回再隐藏 | P0 | 越权分片 0 命中（用例 + SQL 执行计划佐证） |
| FR-INT-09 | 写接口（#03/#05/#06/#20/会话写）必须支持以原 `request_id` + 完全相同正文重试；生成超时（默认 60 秒）不得丢请求，必须可经 #15 查询结果 | P0 | 超时后查询返回执行中/最终结果；重试幂等验证 |
| FR-INT-10 | `DELETE` 接口必须接收 JSON 正文；反向代理不得丢弃、不得改写路径 | P0 | 经网关后仍能读取正文（上线检查单验证） |

### 5.2 审计与安全头校验（FR-AUD）★ 本期新增域

> 背景要求：**业务系统对接的接口必须使用当前系统的日志审计；审计部分需要扩展，以支持对 HTTP 安全头的校验留痕。**

| 编号 | 需求 | 优先级 | 验收标准 |
| --- | --- | --- | --- |
| FR-AUD-01 | 全部 20 个 `/v1/*` 对接接口必须纳入统一接口日志审计（`sbp_ai_system_api_log`），不得跳过 | P0 | 任意调用后审计表可检索到对应记录（含 2xx 与 4xx/5xx） |
| FR-AUD-02 | 审计记录必须扩展鉴权维度：`auth_mode`（jwt/hmac）、`client_id`（签名调用方）、`request_id`（契约追踪 ID）；`username` 字段对 HMAC 调用填 `client_id` | P0 | /v1 审计记录三字段非空；管理端 JWT 调用 `auth_mode=jwt` |
| FR-AUD-03 | 审计记录必须包含 HTTP 安全头校验结果（`security_check` 结构化字段）：四头存在性、时间窗偏差（毫秒）、nonce 首用/重放判定、签名比对结果、失败错误码 | P0 | 构造缺头/过期/重放/错签四类请求，审计中 `security_check` 分别记录对应失败原因 |
| FR-AUD-04 | 被安全校验拒绝的请求（401/409）必须同样落审计，且含被拒原因；签名值本身只留摘要（前 8 位 + 后 4 位），nonce 全量留存供重放取证 | P0 | 被拒请求在审计表可检索并还原拒绝原因；审计中无完整签名密文 |
| FR-AUD-05 | 审计写入必须与业务事务隔离（独立会话异步落库），写失败只记应用日志、不影响主请求 | P0 | 主库事务回滚场景下审计仍留存；审计库故障不阻断业务 |
| FR-AUD-06 | 审计中的请求/响应体必须沿用既有脱敏与截断策略（敏感字段掩码、超长截断），日志不落密钥与全文原文 | P0 | 抽检审计记录无密钥、无未脱敏 PII |
| FR-AUD-07 | 审计必须可按时间 / `client_id` / 路径 / `request_id` / 校验结果组合检索，支撑 UC-12 安全追溯 | P1 | 组合查询用例通过，含"某调用方当日全部被拒请求" |

### 5.3 知识接入（FR-KB）

| 编号 | 需求 | 优先级 | 验收标准 |
| --- | --- | --- | --- |
| FR-KB-01 | 必须支持文档与 FAQ 两类来源（`resource_type`）提交解析任务（#01），携带完整 `metadata`，返回 `202` 与 `job_id` | P0 | 同一 `job_id` 重复提交不重复执行 |
| FR-KB-02 | 解析任务必须具备状态机：`queued/running/succeeded/failed`，并暴露 `progress`（#02 可轮询完整结果） | P0 | 各态可构造并查询到 |
| FR-KB-03 | 解析失败必须以任务态呈现（`error_code`/`error_message`），与请求级错误（4xx/5xx）区分 | P0 | 非法文件返回任务失败而非 4xx/5xx |
| FR-KB-04 | 解析产物 `chunks` 必须包含 `seq`、`heading`、`content`、`page_from`、`page_to`、`source_type`，且不得含向量 | P0 | 结构与契约一致；响应体中无向量字段 |
| FR-KB-05 | 首次发布走 #03（已有 `publication_id` 返回 409，不得隐式覆盖）；修订前经 #04 读取基线，修订走 #05（基线冲突 409）；整单删除走 #06；单片删除通过 #05 提交移除后的完整集合 | P0 | 四条写入路径语义用例通过 |
| FR-KB-06 | 写入必须校验修订顺序（`record_id`/`base_record_id` 基线、`revision` 单调）；旧版本迟到事件被拒且不污染现网版本 | P0 | 乱序事件被拒（409） |
| FR-KB-07 | 新快照必须原子生效：AI 写入并向量化完成返回回执，GSI 切换发布指针；切换前检索继续用旧内容；失败保留旧生效快照 | P0 | 并发检索+切换用例无中间态命中 |
| FR-KB-08 | 删除必须保留幂等墓碑：DELETE 后迟到的 CREATE/UPDATE 不得复活已删除数据；空集合不能作为正常发布 | P0 | 删除后重放写入被拒 |
| FR-KB-09 | 相同 `content_hash` 的切片不得重复向量化；回执给出 `searchable` 与 `accepted_chunk_count` | P1 | 重复内容二次提交计数正确、耗时可测下降 |

### 5.4 检索与问答（FR-RAG）

| 编号 | 需求 | 优先级 | 验收标准 |
| --- | --- | --- | --- |
| FR-RAG-01 | 必须支持两种检索模式：关键词检索与自然语言检索（#07），返回 `snippet` 与 `score` | P0 | 两模式均可返回结果 |
| FR-RAG-02 | 自然语言模式必须向量召回 + RRF 融合 + rerank 精排 | P0 | 关闭 rerank 与开启的结果排序有差异且可复现 |
| FR-RAG-03 | 召回为空或最高分低于阈值时必须返回"无依据"（`no_evidence`），禁止生成推测答案 | P0 | 库外问题 20 例抽查 0 编造 |
| FR-RAG-04 | 生成必须为非流式（#14）；`stream=true` 返回 `UNSUPPORTED_STREAM` | P0 | 参数校验用例通过 |
| FR-RAG-05 | 答案必须附带引用（条目标识、分片标识、标题、片段），引用编号与正文标记一一对应；校验基准为 AI 侧已授权完整切片正文 | P0 | 引用可定位到分片；伪造编号被拒 |
| FR-RAG-06 | 会话必须支持创建/分页列表/详情（含历史分页）/改名/删除/清空（#08–#13） | P0 | 会话六操作用例通过 |
| FR-RAG-07 | 会话多轮上下文按 token 预算截断，保留系统指令与最近轮次 | P1 | 长会话不超模型上下文；关键指令不丢 |
| FR-RAG-08 | 历史消息中若其知识依赖已失效（发布指针切换/停用/删除），该条回答与引用必须整条隐藏 | P1 | 停用知识后查询历史不返回该回答 |

## 十一、需求验收流程

1. **自测**：开发按本文 §五、§八逐条构造用例，产出执行记录；
2. **联调**：GSI 按 UC-11 逐接口验收，差异记入缺陷清单；
3. **业务抽检**：质检团队按规则抽样 20–30 通，验证判定与证据可读性；
4. **安全审计演练**：按 UC-12 抽取被拒请求样本，核验安全头校验留痕；
5. **验收签字**：四项通过后由业务负责人确认；未通过项列入二期或走变更。
