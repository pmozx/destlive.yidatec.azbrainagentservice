# 03 · 日志审计与接入追踪 · 接口清单

> 本文是**调用契约**：11 个端点怎么调、参数怎么传、返回什么、错在哪。
> 字段含义见 [`02-数据模型与表关系.md`](02-数据模型与表关系.md) §3；状态取值见 [`01-业务功能说明.md`](01-业务功能说明.md) §五。
> 端点实现：`app/modules/system/api_log/controller.py`、`app/modules/system/access_trace/controller.py`。

---

## 一、全局约定

| 项 | 约定 |
| --- | --- |
| 前缀 | `/api/v1/system`（管理台 JWT 侧，非 `/v1` 契约） |
| 鉴权 | 管理台登录态（JWT），审计**不校验数据权限**，有权限进页面即可查全量 |
| 方法 | 查询用 `GET` + query；批量删除用 `DELETE` + JSON body；清理用 `POST` + JSON body |
| 响应包装 | `{ "code": 0, "msg": "...", "data": ..., "status_code": 200, "success": true }`（`app/common/response.py::ResponseSchema`） |
| 成功码 | `code=0`（`RET.OK`）；HTTP 状态 200 |
| 时间格式 | **输出** `YYYY-MM-DD HH:MM:SS`（无时区后缀，库内是 `timestamptz`，按 UTC 存、格式化输出）；**输入**同格式字符串 |
| 分页参数 | `page_no`（默认 1，≥1）、`page_size`（默认 10，1–100）、`order_by`（JSON 数组字符串，如 `[{"id":"desc"}]`） |
| 分页返回 | `{ page_no, page_size, total, has_next, items[] }`（`PageResultSchema`） |
| 时间范围 | `created_time` / `updated_time` 传数组 `["2026-11-01 00:00:00","2026-11-02 00:00:00"]` |
| 已记录审计 | 本组接口自身也受审计：`DELETE`/`POST` 会新增一条 `api_log`（只记一次，不会递归） |
| 错误响应 | `{ "code": 非0, "msg": "...", "data": null, "status_code": 5xx, "success": false }`；**注意**：业务异常默认 500，见 §3.2 |

## 三、逐端点

### 3.1 F1 审计行分页 `GET /api-log/list`

**Query 参数**

| 名 | 类型 | 必填 | 约束 | 说明 |
| --- | --- | --- | --- | --- |
| `page_no` | int | 否 | ≥1，默认 1 | 页码 |
| `page_size` | int | 否 | 1–100，默认 10 | 每页条数 |
| `order_by` | str | 否 | JSON 数组字符串 | 默认 `[{"id":"desc"}]` |
| `request_path` | str | 否 | 模糊 | 路径，`LIKE` |
| `request_method` | str | 否 | 精确 | `GET`/`POST`/… |
| `username` | str | 否 | 模糊 | 操作人 |
| `status` | int | 否 | 0/1 | 0 成功 1 失败 |
| `response_code` | int | 否 | 100–599 | 精确 |
| `request_ip` | str | 否 | 模糊 | 来源 IP |
| `created_time` | str[] | 否 | `["起","止"]` | 创建时间范围 |
| `updated_time` | str[] | 否 | 同上 | 本表有该列，可正常使用 |

**响应 `data`**：`PageResultSchema<SystemApiLogOutSchema>`，`items[]` 字段：`id`、`uuid`、`created_time`、`updated_time`、`is_deleted`、`deleted_time`、`username`、`status`、`description`、`request_path`、`request_method`、`response_code`、`process_time`、`request_ip`。

**不返回** `request_payload` / `response_json` / `request_query` / `user_agent`（体积原因，要看去 F2）。

```json
{
  "code": 0, "msg": "查询接口审计日志成功", "status_code": 200, "success": true,
  "data": {
    "page_no": 1, "page_size": 2, "total": 128, "has_next": true,
    "items": [
      {
        "id": 12034, "uuid": "9f2c1b7e4a6d4c8f9b0e1a2c3d4e5f60",
        "created_time": "2026-11-02 10:41:07", "updated_time": "2026-11-02 10:41:07",
        "is_deleted": false, "deleted_time": null,
        "username": "gsi-service", "status": 0,
        "description": "05-知识检测与确认", "request_path": "/v1/knowledge/detect",
        "request_method": "POST", "response_code": 200,
        "process_time": "38.4ms", "request_ip": "10.20.31.7"
      }
    ]
  }
}
```

**错误**：`401`（未登录，由鉴权层返回）；`422`（`page_size>100` 等参数越界）。

### 3.2 F2 审计详情 `GET /api-log/detail/{id}`

| 位置 | 名 | 类型 | 约束 |
| --- | --- | --- | --- |
| path | `id` | int | ≥1 |

**响应 `data`**：F1 的字段 + `request_query`、`request_payload`、`response_json`、`user_agent`。

```json
{
  "code": 0, "msg": "获取接口审计日志详情成功", "data": {
    "id": 12034, "username": "gsi-service", "status": 0,
    "description": "05-知识检测与确认", "request_path": "/v1/knowledge/detect",
    "request_method": "POST", "response_code": 200, "process_time": "38.4ms",
    "request_ip": "10.20.31.7",
    "request_query": "", 
    "request_payload": "{\"body\": {\"request_id\": \"req-20261102-0031\", \"scope_id\": \"kb-space-01\", \"password\": \"******\"}}",
    "response_json": "{\"request_id\": \"req-20261102-0031\", \"data\": {\"searchable\": true}}",
    "user_agent": "python-requests/2.32.3"
  }
}
```

> `request_payload` 是**字符串**（内含 JSON），不是对象；前端需要 `JSON.parse`。敏感键已替换为 `******`，超过 2000 字符会带 `...(已截断, 原长 N 字符)`。

**错误**：id 不存在 → `get_or_404` 抛 `CustomException`，**当前返回 HTTP 500**（`code=500`，`msg="接口审计日志不存在"`），而非 404。这是已知问题（见 `04` 报告 P0-5），前端按 `msg` 展示而不是按状态码分支。

### 3.3 F3 批量删除 `DELETE /api-log/delete`

Request body 直接是 ID 数组：

```json
[12031, 12032]
```

**响应**：`data=null`，`msg="删除接口审计日志成功"`。

**错误**：空数组 → `CustomException("删除失败，删除对象不能为空")` → HTTP 500。

> 物理删除，不可恢复。删除前请确认不是正在取证的记录（取证期建议只做时间范围清理，保留可追溯性）。

### 3.4 F4 按保留天数清理 `POST /api-log/clean`

```json
{ "days": 90 }
```

| 名 | 类型 | 必填 | 约束 | 说明 |
| --- | --- | --- | --- | --- |
| `days` | int | 否 | 1–3650，默认 90 | 早于 `now - days` 的行被物理删除 |

**响应**：`data` 为删除条数（int），`msg="已清理 N 条过期接口审计日志"`。

```json
{ "code": 0, "msg": "已清理 1284 条过期接口审计日志", "data": 1284, "status_code": 200, "success": true }
```

**错误**：`days ≤ 0` 被 Pydantic 拦截（422）；service 层还有一次 `days<=0` 校验（500）。

### 3.5 F5 近 N 小时概览 `GET /access-trace/summary`

| 名 | 类型 | 必填 | 约束 | 说明 |
| --- | --- | --- | --- | --- |
| `hours` | int | 否 | 1–168，默认 24 | 统计窗口 |

**响应 `data`（9 个计数）**

```json
{
  "window_hours": 24,
  "call_total": 1842, "call_failed": 37,
  "signature_failed": 5, "nonce_reused": 2, "idempotency_conflict": 3,
  "nonce_registered": 1801,
  "request_running": 0, "idempotency_processing": 1, "idempotency_tombstone": 12
}
```

口径提醒：

- 除 `nonce_registered` / `request_running` / 幂等两个计数外，其余 5 个都只统计 **`/v1/*`** 的调用（管理台调用不计入）。
- `request_running` **当前恒为 0**（结果台账无写入方）。
- `idempotency_tombstone` 统计**全表**墓碑数，不受 `hours` 限制（墓碑没有过期时间）。

### 3.6 F6 契约调用明细分页 `GET /access-trace/calls`

| 名 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `page_no` / `page_size` / `order_by` | — | 否 | 同 F1 |
| `request_id` | str | 否 | 模糊 |
| `request_path` | str | 否 | 模糊；**不传 → 只查 `/v1/%`**，传了 → 按条件查（可回溯 `/api/v1`） |
| `request_method` | str | 否 | 精确 |
| `client_id` | str | 否 | 模糊 |
| `auth_mode` | str | 否 | `jwt` / `hmac` |
| `status` | int | 否 | 0/1 |
| `response_code` | int | 否 | 精确 |
| `signature_result` | str | 否 | `passed` / `failed` / `skipped`（JSONB 过滤） |
| `nonce_state` | str | 否 | `first_use` / `reused` / `not_checked`（JSONB 过滤） |

**响应 `items[]`**：`id`、`created_time`、`username`、`status`、`description`、`request_path`、`request_method`、`response_code`、`process_time`、`request_ip`、`auth_mode`、`client_id`、`request_id`、`security_check`（对象）。

```json
{
  "id": 12034, "created_time": "2026-11-02 10:41:07",
  "username": "gsi-service", "status": 1, "description": "05-知识检测与确认 | UNAUTHORIZED",
  "request_path": "/v1/knowledge/detect", "request_method": "POST",
  "response_code": 401, "process_time": "2.1ms", "request_ip": "10.20.31.7",
  "auth_mode": "hmac", "client_id": "gsi-service", "request_id": "req-20261102-0031",
  "security_check": {
    "headers_present": ["X-AI-Signature", "X-AI-Signature-Version", "X-AI-Client-Id", "X-AI-Timestamp"],
    "timestamp_deviation_ms": 412,
    "nonce_state": "not_checked",
    "signature_result": "failed",
    "signature_digest": null,
    "failure_code": "UNAUTHORIZED"
  }
}
```

> `headers_present` 里少一个头，基本可直接定位"缺头"而不是"签名算错"。

### 3.7 F7 调用详情 `GET /access-trace/calls/detail/{id}`

F6 字段 + `request_query`、`request_payload`、`response_json`、`user_agent`。错误行为同 F2（查不到 → 500 + 业务 msg）。

### 3.8 F8 防重放台账 `GET /access-trace/nonces`

| 名 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `client_id` | str | 否 | 模糊 |
| `nonce` | str | 否 | 模糊 |
| `request_id` | str | 否 | 模糊 |

**响应 `items[]`**：`id`、`client_id`、`nonce`、`request_id`、`created_time`、`expires_at`。

```json
{ "id": 88213, "client_id": "gsi-service", "nonce": "5f1c9b2e7a4d4c2e",
  "request_id": "req-20261102-0031", "created_time": "2026-11-02 10:41:07",
  "expires_at": "2026-11-02 10:51:07" }
```

> **一条 = 一次首用**。重放不会新增行，重放证据在 F6 的 `nonce_state=reused`。`request_id` 可能为 `null`。

### 3.9 F9 幂等台账 `GET /access-trace/idempotency`

| 名 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `scope` | str | 否 | `job` / `request` / `event` |
| `biz_id` | str | 否 | 模糊 |
| `status` | str | 否 | `processing` / `succeeded` / `failed` / `tombstone` |
| `body_hash` | str | 否 | 模糊 |

**响应 `items[]`**：`id`、`scope`、`biz_id`、`body_hash`、`status`、`result_ref`、`created_time`、`expires_at`。

```json
{ "id": 5120, "scope": "request", "biz_id": "req-20261102-0031",
  "body_hash": "3b1f0e9c…（64 位 hex）", "status": "succeeded",
  "result_ref": { "status_code": 200, "body": { "request_id": "req-20261102-0031", "data": { "searchable": true } } },
  "created_time": "2026-11-02 10:41:06", "expires_at": "2027-01-31 10:41:06" }
```

> 排查 409 的口诀：`status=processing` → 上次没释放/还在跑；`succeeded` 但 `body_hash` 不同 → 真·异正文冲突；`expires_at=null` → 墓碑（删除类，永不清）。

### 3.10 F10 结果台账 `GET /access-trace/request-logs`

| 名 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `request_id` | str | 否 | 模糊 |
| `operation` | str | 否 | `completion` / `mutation` / `delete` |
| `status` | str | 否 | `running` / `succeeded` / `failed` / `expired` |
| `error_code` | str | 否 | 精确 |

**响应 `items[]`**：`id`、`request_id`、`operation`、`status`、`result_visible`、`result_ref`、`error_code`、`created_time`、`expires_at`。

> **当前恒返回空列表**：该表无写入方（`01` §八 L4）。接口本身可用，不要据此判断"没有超时请求"。

### 3.11 F11 四表时间线 `GET /access-trace/timeline`

| 名 | 类型 | 必填 | 约束 |
| --- | --- | --- | --- |
| `request_id` | str | **是** | 1–64 字符 |

**响应 `data`**

```json
{
  "request_id": "req-20261102-0031",
  "found": true,
  "calls": [ { "id": 12034, "response_code": 401, "security_check": { "…": "…" } } ],
  "nonces": [],
  "idempotency": [ { "scope": "request", "biz_id": "req-20261102-0031", "status": "processing" } ],
  "request_logs": []
}
```

- `found` 为四段任一非空；全空不是错误（HTTP 200 + `found=false`），页面提示"未找到"。
- 每段最多 20 条，按 `id desc`。
- `idempotency` 段用"`biz_id` 等值 + `biz_id` 前缀"双条件，因此可能比精确匹配多返回行（见 `02` §4.2 R3 边界）。

**错误**：`request_id` 为空 → `CustomException("请填写要追踪的 request_id")` → 500（参数层 `min_length=1` 已先拦一次，实际多为 422）。

## 五、调用顺序建议（排障 SOP）

**场景 A：调用方说"我调失败了"**

1. `GET /access-trace/timeline?request_id=<对方给的 ID>` → 看四段是否齐全、`response_code`、`failure_code`。
2. 若 `calls` 为空 → 请求没到服务端（网关/地址错），转查网关日志。
3. 若 `security_check.failure_code=UNAUTHORIZED` 且 `timestamp_deviation_ms` 超 300000 → 时钟问题。
4. 若 `nonce_state=reused` → 对方复用了 nonce，去 F8 查该 nonce 的首用时间。
5. 若 `response_code=409` → 去 F9 按 `biz_id` 查状态：`processing`（上次没释放）/ `succeeded`（正文变了）。

**场景 B：审计里某条数据可疑**

1. F1 按 `request_path` + 时间范围定位行。
2. F2 看 `request_payload` / `response_json`（注意已脱敏、可能截断）。
3. 需要关联契约台账时，取该行 `request_id` 走 F11。

**场景 C：表体积过大**

1. F5 看 `call_total` 量级。
2. `POST /api-log/clean {"days": 30}` 缩短保留期（一次性）。
3. 若要长期生效，改 `API_LOG_RETENTION_DAYS` 并重启（启动时才清理）。
