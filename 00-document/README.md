## 二、命名规范

### 2.1 目录

| 层级 | 规则 | 示例 |
| --- | --- | --- |
| 顶层 | `NN-<中文主题>文档`，两位序号，按阅读顺序从 `00` 起连续，不跳号 | `01-服务大脑AI项目需求与架构文档` |
| 子目录 | `NN-<中文主题>`，序号与同级文档**共用同一序列** | `01-…/05-接口契约与数据基线/` |
| 索引 | 固定命名 `README.md`，不参与编号 | 每个目录一份 |

### 2.2 文档

| 类型 | 规则 | 示例 |
| --- | --- | --- |
| 正文 | `NN-<主题>.md`，目录内从 `01` 连续编号，**不跳号、不复用** | `02-接口交付范围与工时评估.md` |
| 素材三件套 | `NN-<主题>-原件.<ext>` / `-概要.md` / `-详尽版.md`，同一 `NN` 共用主题名 | `02-质检需求说明书-原件.pdf` / `-概要.md` / `-详尽版.md` |
| 台账/记录 | 同上，只追加不改写（如周报） | `04-项目周报.md` |
| 脚本 | 跟随其产物目录，放 `scripts/` 子目录 | `02-…/scripts/gen_kb_plan_xlsx.py` |

### 2.3 禁止项

- 文件名内**禁止空格、下划线、括号、`·`**：`02 服务大脑质检需求说明书v1.0.pdf` ✗
- **禁止双段编号**：`01-1-接口交付范围…` ✗（原「第 1 章第 1 篇」式编号已废止，一律目录内单序号）
- **禁止临时词**：`tmp`、`新建`、`副本`、`final`、`旧版`；调试残留（如 `tmp_err.txt`）不得入库
- **版本不进文件名**：文档版本写在文首「版本 / 变更记录」行；唯一例外是对外契约手册，用 `-v2` 标契约大版本（`01-知识平台与AI接口参数手册-v2.md`）
- **禁止 `integration` 等已废弃域名词**留在路径或标题中

### 2.4 引用写法

| 场景 | 写法 |
| --- | --- |
| 同目录引用 | `01-团队开发规范.md` 或简称 `01` |
| 跨目录引用（正文提及） | `目录号-文档号`，如 `02-03` = `02-…/03-知识平台开发计划与说明.md` |
| 跨目录引用（可点击） | 相对路径 Markdown 链接，如 `[开发计划](02-服务大脑AI项目开发计划文档/03-知识平台开发计划与说明.md)` |
| 模块内引用 | `模块号/文档号`，如 `05-02/02` = 05 目录下 02 模块的数据模型文档；同模块内直接写文件名 |
| 引用章节 | `02-03 §四 里程碑` |

> 重命名或移动文档时，必须同步更新所有引用方（含 `backend/app/modules_api/contract/` 下脚本的默认留档路径）与所属目录 README。

## 三、新增文档该放哪（归属判定）

| 文档性质 | 去向 | 判据 |
| --- | --- | --- |
| 客户/上游给的原件或摘要 | `00-` | 只读，不由本项目改写 |
| 需求、架构、模块、表结构、对外契约与数据基线 | `01-` | 描述「系统应该是什么样」 |
| 范围、工时、排期、里程碑、甘特 | `02-` | 描述「什么时候、多少成本」 |
| 编码/框架/数据库/LLM 使用规则（前瞻约束） | `03-` | 描述「代码应该怎么写」 |
| 会议纪要、阶段验证记录、验收证据、评审/审计报告、周报 | `04-` | 描述「实际发生了什么」 |
| 已完成模块的 as-built 说明（功能、表关系、接口、实现与排障） | `05-` | 描述「现在跑的是什么」，以代码为准 |

边界说明：

- **规范 vs 报告**：`03` 放规则（今后必须遵守），`04-03` 放存量问题证据（对已有代码的评审结论）；规范的「存量整改」条目引用报告编号，报告不反向定义规则。
- **计划 vs 过程**：`02` 是事前承诺（可改，改后留痕），`04` 是事后证据（只追加，不改写）。
- **设计 vs 说明书**：`01` 写「系统应该是什么样」（可含未实现规划），`05` 写「代码里现在是什么样」（只写已实现）；两者冲突时以 `05` 反映的现实为准，并回头修订 `01`。

## 四、维护约定

1. **README 是索引唯一来源**：新增、重命名、删除文档时，同一次提交内更新所属目录 `README.md`；顶层目录增删时更新本文件。
2. **只读区不改写**：`00-` 的原件与 `01-…/05-` 的外部契约文件属外部输入，契约变更先登记在 `02-01` 复核结论，再同步本侧文档。
3. **追加型文档不覆盖**：`04-…/04-项目周报.md` 只追加；验收记录由脚本 `--record` 生成，重跑另存新文件。
4. **一次提交只做一件事**：目录重命名/批量移动单独成一次提交，避免与内容修订混在一起，便于追溯。
5. **提交前自查**：`grep` 旧路径无残留 + 所有 README 中的文件真实存在 + 相对链接可打开。
